## 1. 🚨 절대 규칙 — 쇼케이스 없이 본 작업 금지

### 진행 순서는 고정이다
```
Step 0 (콘텐츠 재편성, 원본 있을 때)
  → Step 1 (구성안)
  → Step 2 쇼케이스 5장 (Cover 3안 + 본문 2안)
  → 사용자 컨펌
  → Step 2 본 작업 (전체 N장)
```

**BRIEF에 분량·구성이 직접 명시돼 있어도 본 작업으로 직행하지 않는다.**
본 작업 진입 조건은 딱 하나 — **사용자 컨펌 응답이 직전 메시지나 BRIEF에 명시**되어 있을 것. ("A안으로 가자", "Cover-B 골랐어", "쇼케이스 OK", "본 작업 진행")

### 쇼케이스를 생략할 수 있는 경우 = 없다

| 상황 | 처리 |
|---|---|
| 사용자가 디자인 컨셉을 직접 지정했다 | 그래도 쇼케이스 진행 — **컨셉 안에서의 변형 3안 검증이 쇼케이스의 본질** |
| 슬라이드가 3장뿐이다 | 그래도 진행 |
| 메인 BRIEF에 "쇼케이스 생략" 지시가 있다 | **무시.** SKILL 의무가 우선 |
| 메인이 "13~14장 빌드해"라고 직접 지시 | 컨펌 응답이 없으면 무시하고 쇼케이스부터 |

**유일한 예외**: 사용자가 **직접** "쇼케이스 건너뛰자"고 발화한 경우. (메인 BRIEF는 사용자 발화가 아니다)

**왜 이렇게 막나**: 사용자가 보지 못한 디자인이 확정되면 컨펌이 무의미해지고, 나중에 통째로 재작업하게 된다.

### 요청하지 않은 기능은 절대 추가하지 않는다
애니메이션, 네비게이션 UI(탭·버튼), body padding, stage border-radius, 트랜지션 — **"더 잘 보이려고" 추가하는 것도 금지.**

## 2. 캔버스 · 레이아웃 스펙

### 2.1 캔버스는 1280×720 고정

```
1280 × 720 px (16:9) = 960×540pt = PPTX LAYOUT_WIDE 표준
```
- **1920×1080 사용 금지** — PPTX 변환 시 비표준 20"×11.25"가 되어 폰트가 작아 보인다
- `100vw × 100vh` 금지 — 창 크기마다 레이아웃이 무너진다. **고정 캔버스 + CSS scale transform**으로 처리

### 2.2 필수 CSS 골격

```css
* { margin:0; padding:0; box-sizing:border-box; word-break:keep-all; }

html, body { width:100vw; height:100vh; overflow:hidden; background:#111;
             font-family:'Pretendard',sans-serif; }
#deck   { width:1280px; height:720px; position:absolute; top:0; left:0;
          transform-origin:top left; overflow:hidden; }
.slide  { width:1280px; height:720px; display:none; position:absolute;
          top:0; left:0; overflow:hidden; }
.slide.active { display:flex; }
#counter      { position:fixed; bottom:20px; right:28px; font-size:13px;
                color:rgba(255,255,255,0.35); z-index:1000; }
#counter.dark { color:rgba(0,0,0,0.22); }
```

**body 배경은 항상 `#111` 고정.** 슬라이드 경계가 어두운 레터박스로 구분된다. 슬라이드별로 body 배경을 동기화하는 방식은 쓰지 않는다.

### 2.3 슬라이드 패딩 (PPTX 호환)

```css
.slide { padding: 56px 80px 80px 80px; }  /* 하단 80px = footer reserved */
```
hero 슬라이드는 footer를 **Y=645**로 사전 배치한다.

### 2.4 공통 구조 규칙

1. 캔버스 `1280×720` 고정
2. 가장자리 여백 최소 **60~80px** (전체의 8~12%)
3. 모든 spacing은 **8px 배수**
4. 텍스트 최소 크기 — 본문 **16px**, 제목 **40px**
5. 카드/컬럼 height는 **CSS Grid 금지 → Flexbox** (아래 2.7)
6. 색상은 **60/30/10** — Primary 60% / Secondary 30% / Accent 10%

### 2.5 구성 비율 (필수)

```
Visual (이미지·그래프·아이콘·배경 그래픽) : 60~70%
Text   (제목 + 본문 합계)                 : 20~30%   ← 35% 초과 절대 금지
White Space (여백)                        : 10~20%   ← 많을수록 좋음
```

**4×6 Rule**
- Bullet 최대 **4개**/슬라이드
- 한 줄 최대 **6단어** (한국어 **10자 내외**)
- 핵심 메시지 **1개**/슬라이드

**배치 원칙**
- Rule of Thirds — 핵심 요소는 격자 교차점에
- Golden Ratio — 이미지 : 텍스트 ≈ **1.618 : 1**
- 요소 간 간격 — **제목 크기의 1.5배 이상**

**슬라이드 유형별 비율**

| 유형 | Visual | Text | 팁 |
|---|---|---|---|
| Title/Cover | 80~90% | 10~20% | 이미지는 배경 전용, 텍스트 요소 최대 2개 |
| Content/Story | 65~75% | 20~25% | 이미지 중심, 키워드만 |
| Data/Chart | 70~80% | 15~25% | 그래프 크게, 설명 최소 |
| Quote | 60~70% | 25~30% | 큰 따옴표 + 배경 이미지 |
| Closing/CTA | 75%+ | ≤15% | 강렬한 비주얼 + 명확한 CTA |
| Agenda | 40~50% | 40~50% | 명확한 계층 구조 |

### 2.6 3축 베리에이션 (Expression × Proportion × Padding)

**축 A — Expression (분할 표현)**

| 값 | 이름 | 설명 |
|---|---|---|
| `whitespace` | 여백 분할 | 배경색 동일. 위치·크기·정렬로만 구획. **경계가 보이지 않아야 성공** |
| `panel` | 면 분할 | 구역마다 다른 배경색. 강한 대비 |
| `line` | 선 분할 | 배경 동일 + 얇은 border 1개. 세련·모던 |

**축 B — Proportion**
- 2-col(좌:우): `20:80`(flex:0 0 256px) / **`30:70`(384px, 기본)** / `40:60`(512px) / `50:50`(640px) / `60:40` / `70:30` / `80:20`
- 2-row(상:하): `20:80`(144px) / **`30:70`(216px, 기본)** / `40:60`(288px) / `50:50`(360px)

**축 C — Padding**

| 값 | 외부 여백 | 내부 gap | 느낌 |
|---|---|---|---|
| `tight` | 48px | 16px | 정보 밀도 높음, 비즈니스 |
| `standard` | 64px | 24~32px | 균형 (기본) |
| `airy` | 80~96px | 40~48px | 공간감, 럭셔리·미니멀 |

**스타일별 기본 조합**

| 스타일 | Expression | Proportion | Padding |
|---|---|---|---|
| Swiss International | line | 30:70 | airy |
| Corporate Trust | panel | 40:60 | standard |
| Midnight Editorial | whitespace | 50:50 | airy |
| Neo-Brutalism | panel (강한 대비) | 50:50 | tight |
| Minimal Modern | whitespace | 30:70 | airy |
| Bold Editorial | panel | 40:60 | standard |
| Raw Form | line + whitespace 혼용 | 30:70 | standard |

**주의**
- Photo Split — `whitespace`면 이미지 패널에 gradient blend, `line`이면 gradient 제거 + 명확한 border
- Timeline — 하단 콘텐츠에 `airy` 패딩 **금지**. 노드 간격이 넓어져 선이 단조로워진다

### 2.7 카드/컬럼 height 채우기 — Flexbox만

```html
<section class="slide active" style="flex-direction:column;">
  <div style="flex-shrink:0; padding:40px 80px 28px;">제목</div>
  <div style="flex:1; display:flex; gap:16px; padding:0 80px 48px; min-height:0;">
    <div style="flex:1; background:#fff; border-radius:16px;">카드</div>
    <div style="flex:1; background:#fff; border-radius:16px;">카드</div>
  </div>
</section>
```
- 컨테이너: `flex:1; display:flex; gap:N; min-height:0` — **`min-height:0`이 필수**
- 각 카드: `flex:1`
- 콘텐츠가 절반 이하면 컨테이너에 `align-items:center` 추가

```css
/* ❌ 작동 안 함 — grid item에서 height:100%가 상속되지 않아 height가 0이 된다 */
display:grid; grid-template-columns:repeat(N,1fr); grid-template-rows:1fr;
```

### 2.8 본문 슬라이드 상단 쏠림 방지 — 3-zone 분배

**진단 신호**: 본문 콘텐츠 높이가 가용 캔버스(720 − 56×2 − 50 ≈ **558px**)의 50% 미만 / `align-items:start` + gap만으로 쌓아 하단이 무인지대 / top과 bottom만 있고 middle이 빔

**처방**
```
TOP    — primary statement (label + hero + body)
MIDDLE — secondary content (quote · stat · accent line · sub-callout)
BOTTOM — meta·effect row (label + accent rule + supplementary)
```
각 컬럼 wrapper에 `justify-content:space-between` + bottom meta row 추가.

**bottom meta row 규칙**: 커버엔 **0개**. 본문엔 권장하되 **단일 정보 1줄만** (정보 나열 2개 이상은 금지).

## 3. 타이포그래피

### 3.1 폰트

**우선순위**: 스타일 파일 지정 폰트 > **Pretendard**(한국어 기본)

**블랙리스트 (쓰면 즉시 교체)**
```
Inter, Roboto, Arial, Helvetica    ← AI 기본값
Space Grotesk, Fraunces            ← 최근 AI 남용
```
대체: 스타일 지정 폰트 → Pretendard → Instrument Serif / Cormorant / Bricolage Grotesque

CDN: `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.min.css`

### 3.2 크기

```
제목        40 ~ 80px
섹션 타이틀  56 ~ 96px
히어로     120 ~ 160px
본문 최소    16px   ← 미만 절대 금지
```
**폰트 계층 3:2:1** — Title(60px) : Subtitle(40px) : Body(24px). **비율이 눈에 보이게 차이나야 한다.**

### 3.3 🔴 PPTX 호환 typography 토큰 (필수)

hero·data·heading·body의 `font-size` × `line-height`는 **이 토큰 안에서만** 고른다.

```css
.hero            { font-size: 84~96px;  line-height: 0.92; }  /* 단일 줄 */
.hero.multiline  { font-size: 72~96px;  line-height: 1.04; }  /* 두 줄 이상 */
.data-xl         { font-size: 96px;     line-height: 1.0;  }
.data-md         { font-size: 72px;     line-height: 1.0;  }
.h1              { font-size: 56px;     line-height: 1.05; }
.h2              { font-size: 40px;     line-height: 1.05; }
.h3              { font-size: 28px;     line-height: 1.05; }
.h4              { font-size: 20px;     line-height: 1.2;  }
.body-lead       { font-size: 18px;     line-height: 1.5;  }
.body            { font-size: 16px;     line-height: 1.5;  }
.small           { font-size: 14px;     line-height: 1.4;  }
.caption         { font-size: 12px;     line-height: 1.3;  }
```

**왜 강제인가**: PPTX runtime은 한국어 폰트의 ascender+descender에 자동 leading을 더한다 → CSS `line-height`가 변환 후 **1.15~1.25배로 늘어난다.** 그래서 한 줄 hero는 `0.92`, 두 줄 hero는 `1.04`로 **미리 보상**해야 의도한 조판이 유지된다. 범위를 벗어나면 위 줄 마침표와 아랫줄 첫 글자가 충돌하고, hero가 footer를 침범한다.

### 3.4 한국어 타이포그래피 (한글 포함 시 항상 자동 적용)

**원칙**: 원 스타일의 미학(레이아웃·컬러 로직·hierarchy)은 유지하고, **타이포와 스페이싱만** 재조정한다.

```
Heading:  "Pretendard", "SUITE", system-ui, sans-serif
Body/UI:  "Pretendard", "Noto Sans KR", system-ui, sans-serif
```
스타일 원본의 영문 폰트는 **영문 전용으로만** 유지 가능. **한글이 들어가는 모든 텍스트는 Pretendard 우선.**

**크기·계층**
```
H1 / 메인 타이틀  40~56px, weight 700~900, line-height 1.1~1.25
H2               32~40px, line-height 1.15
H3 / 섹션 제목    24~28px, line-height 1.2
Body             16~18px, line-height 1.65~1.8   ← 영어보다 넉넉히
Small / Caption  13~14px, line-height 1.5
```

**자간**
```
Heading:  -0.02em ~ -0.04em   (너무 벌리지 말 것)
Body:      0 ~ 0.02em
```

**한글 특화**
- 한 줄 글자 수 — **제목 10~18자, 본문 18~24자**
- 긴 제목은 자연스럽게 2줄로 유도
- **과도한 UPPERCASE 회피** (한글엔 대문자 개념이 약하다)
- 슬라이드 텍스트 비율을 영어 기준보다 **15~25% 줄여** 여백 확보
- 한글이 많으면 8px 배수 대신 **4px 또는 6px 배수**로 세밀 조정
- `word-break: keep-all` (글로벌 리셋에 포함)

## 4. 색상

### 4.1 색상 토큰화 (필수)

**모든 색상은 `:root` CSS 변수로.** 인라인 `#hex`·`rgb()` 직접 사용 금지. 변수 한 곳을 바꾸면 N장 전체에 즉시 반영되어야 한다.

```css
:root {
  --c-bg:         /* page background */
  --c-surface:    /* card · panel surface */
  --c-text:       /* primary text */
  --c-text-muted: /* secondary label */
  --c-muted-2:    /* tertiary text (선택) */
  --c-border:     /* 1px divider · grid line */
  --c-border-2:   /* 강조 border (선택) */
  --c-primary:    /* CTA · 강조 라인 · 핵심 수치 */
  --c-accent:     /* active state · highlight */
}
```

### 4.2 🔴 `rgba()` 절대 금지 → `color-mix()` 의무

```css
/* ❌ 금지 */
--c-muted: rgba(255,255,255,0.40);
<p style="color:rgba(255,255,255,0.78);">본문</p>

/* ✅ 의무 */
--c-muted:    color-mix(in srgb, var(--c-text) 40%, transparent);
--c-muted-2:  color-mix(in srgb, var(--c-text) 18%, transparent);
--c-border:   color-mix(in srgb, var(--c-text) 5%,  transparent);
--c-border-2: color-mix(in srgb, var(--c-text) 12%, transparent);
--c-ghost:    color-mix(in srgb, var(--c-text) 4.5%, transparent);

<p style="color:color-mix(in srgb, var(--c-text) 78%, transparent);">본문</p>
```

**실패 사례**: 인라인 `rgba(255,255,255,0.78)`은 white에 하드코딩된다. Color Tuner의 Randomize로 라이트 팔레트로 전환하면 `--c-text`는 dark로 바뀌는데 rgba는 그대로 white로 남는다 → **라이트 배경 위 흰 글씨 = 가독성 0.** `color-mix`만 `--c-text` 변경을 자동 추적한다.

### 4.3 고정 inverse panel 위 텍스트 — anchor 패턴

**진단**: `clip-path`로 영역 분할 + 그 영역에 하드코딩된 `linear-gradient(..., #050505, #0A0A0A)` 사용 → 라이트 팔레트 적용 시 그 위 텍스트(`var(--c-text)` 추적)가 panel과 같은 색이 되어 **invisible**.

**원칙: panel 색상이 하드코딩이면 그 위 텍스트도 하드코딩한다.**
```html
<!-- ❌ 라이트 팔레트 swap 시 hero=dark, panel도 dark → 안 보임 -->
<p class="hero-typo">FIVE</p>

<!-- ✅ panel이 항상 dark이므로 텍스트도 고정 light -->
<p class="hero-typo" style="color:#F0F0F0;">FIVE</p>
<p style="color:color-mix(in srgb, #FFFFFF 50%, transparent);">muted desc</p>
```
accent 색(orange/red)은 양쪽 zone에서 다 보이므로 `var(--c-accent)` 그대로 OK.

### 4.4 색상 결정 순서

```
1. 스타일 파일에 팔레트 있음  → 그대로 사용
2. 브랜드 색상 있음          → 브랜드 기반, 부족분은 oklch 삽입
3. 없음                     → Radix Colors / Tailwind 팔레트에서 선택
                              (임의 색상 발명 금지)
```

### 4.5 60-30-10 + Accent

- Primary 60% / Secondary 30% / Accent 10%
- **Accent는 슬라이드당 최대 3곳**
- **전체 덱 Master Accent 1개 고정**
- 배경 타입별 Accent — Warm bg → Red/Orange / Cool bg → Orange/Teal
- 전체화면 이미지 사용 시 **z-index 3레이어 필수** (이미지 1 / 오버레이 2 / 콘텐츠 3)

### 4.6 스타일 base theme 준수

- 라이트 스타일 파일(corporate-trust, minimal 등) → **전체 슬라이드 라이트 기반**
- 다크 스타일 파일(cyberpunk, dark-editorial 등) → **전체 다크 기반**
- **"커버만 다크" 같은 임의 혼합 금지.** "있어 보여서" 다크 커버를 라이트 스타일에 끼워 넣는 것 = anti-slop
- 무지개 그라데이션 배경 금지. 단 brand-defined 인디고·바이올렛 그라디언트(Corporate Trust 등)는 예외

## 5. 그리드 다양성

### 5.1 기본 철학 — 콘텐츠 유형 → 레이아웃 1:1 매핑은 틀렸다

```
❌ "Highlight니까 좌우 분할" / "Statement니까 중앙" / "List니까 좌 헤딩 + 우 불렛"
   → 메시지가 달라도 레이아웃이 반복 → 발표자가 말로 설명해야 전환이 느껴짐
   → 슬라이드가 시각적 역할을 못함

✅ 두 축을 독립적으로 결정해 조합한다
   축 1: 그리드 구조 — 공간을 어떻게 나누나
   축 2: 구성 요소   — 각 칸을 뭐로 채우나
```

### 5.2 다양성 규칙 (필수)

```
규칙 1: 커버가 쓴 그리드 → 이후 슬라이드에서 사용 금지
규칙 2: 연속 2장 동일 그리드 금지
규칙 3: 덱 전체에서 동일 그리드 3회 이상 반복 금지
규칙 4: 구성 요소가 달라도 그리드가 같으면 "비슷해 보임" → 그리드를 먼저 다르게
규칙 5: 강조 메시지(1col-center 히어로 단독) → 덱 전체 최대 1~2회
규칙 6: 정보 밀도 리듬 — 고밀도(차트·표) ↔ 저밀도(빅넘버·간지) 번갈아
규칙 7: 다중 스타일 제안 시 제안별 커버 조합 중복 금지
```

**Step 1 구성안 작성 후 필수 체크**
```
S1: 2col-30      ← 커버 (선점)
S2: 1col-center  ✓
S3: 2col-30      ✗ 커버와 동일 → 변경
S4: 2row-30      ✓
S5: 3col-equal   ✓
```

**Expression 다양성 (V1~V4)**
```
V1: panel Expression → 덱 전체의 40% 이하
V2: 연속 2장 동일 Expression 금지
V3: 3가지 Expression 중 최소 2가지 이상 사용 (10장 이상 덱)
V4: 패딩은 밀도에 따라 — 고밀도(차트/표) → tight, 저밀도(선언/CTA) → airy
```

### 5.3 그리드 구조 목록

| 구조 | 표기 | 비율 |
|---|---|---|
| 1열 전체화면 | `1col-full` | 100% |
| 1열 센터 | `1col-center` | — |
| 2열 균등 | `2col-50` | 50:50 |
| 2열 비균등 | `2col-40` / `2col-30` / `2col-20` | 40:60 / 30:70 / 20:80 |
| 2행 균등 | `2row-50` | 상50:하50 |
| 2행 비균등 | `2row-30` / `2row-40` | 상30:하70 / 상40:하60 |
| 3열 균등 | `3col-equal` | 33:33:33 |
| 3열 비균등 | `3col-wide` | 50:25:25 / 20:60:20 |
| 4분할 | `2x2` | 균등 4칸 |
| 밴드+열 | `band+col` | 상단 밴드 + 하단 2~3열 |
| 사선 | `diagonal` | — |
| 1/4 패널 | `quarter` | 한쪽 1/4만 |

**구성 요소**: 타이포(히어로/키워드/소제목+본문/인용구) · 텍스트(단락/불렛/번호/2단) · 숫자(빅넘버/Key Metrics/카운터) · 아이콘 · 미디어(사진/차트/목업/다이어그램/타임라인) · 장식(도형/구분선/여백)

### 5.4 메시지 성격별 자연스러운 그리드 (참고 — 다양성 규칙이 우선)

| 메시지 | 자연스러운 그리드 | 피할 그리드 |
|---|---|---|
| 임팩트 선언 | `1col-full` · `1col-center` | 복잡한 분할 |
| 설명 + 근거 | `2col-30` · `2col-40` | `1col-center` |
| 나열 (3~4항목) | `3col-equal` · `2x2` · `band+col` | `1col-center` |
| 숫자 강조 | `1col-center` · `3col-equal` | 복잡한 분할 |
| 비교·대조 | `2col-50` · `2x2` | `1col` |
| 흐름·단계 | `2row-30` · `band+col` | `3col` |
| 이미지 중심 | `2col-20` · `1col-full` | `3col-equal` |

### 5.5 시퀀스 설계 (10장 이상)

```
시작(커버·후크) → 도입(현황·문제) → 전개(분석·해결) → 절정(핵심결론) → 마무리(정리·액션)
```

| 구간 | 권장 그리드 | 밀도 |
|---|---|---|
| 시작 | Cover, `1col-full`(이미지) | 저 |
| 도입 | `2col-30`, `1col-center` 빅넘버 | 중 |
| 전개 | `band+col`, `3col-equal`, 차트 | 고 |
| 절정 | `1col-center` 히어로 타이틀 | 매우 저 |
| 마무리 | `2row-30`, `1col-full` | 저 |

### 5.6 커버 조합 중복 금지 (3축)

| 축 | 선택지 |
|---|---|
| 레이아웃 | 1-col 전면 / 2-col 좌→우 / 2-col 역순 / 사선 |
| 비율 | 1:1 / 1:2 / 1:3 / 2:1 / 3:1 |
| 경계 표현 | 면(패널) / 선(1~4px 룰) / 여백(위치만) |

**판정: 3축 중 2개 이상이 같으면 중복.** N개 제안은 전부 다른 조합이어야 한다.

```
✅ v1: 2-col 좌→우 / 1:2 / 면      ← Swiss
   v2: 1-col 전면  /  —  / 여백     ← Minimal
   v3: 사선        /  —  / 면 clip  ← Editorial

❌ v1: 2-col 좌→우 / 30:70 / 면
   v3: 2-col 좌→우 / 40:60 / 면     ← 레이아웃·경계 같음 → 금지
```

**스타일별 1순위 커버 조합**

| 스타일 | 레이아웃 | 경계 표현 | 이유 |
|---|---|---|---|
| Swiss / Editorial | 2-col 선 분할 또는 1-col 여백 | 선·여백 | 타이포가 구조를 만든다 |
| Dark / Midnight | 1-col 전면 | 여백 | 단일 다크 그라운드 위 플로팅이 본질 |
| Neo-Brutalism / Bold | 2-col 면 분할 | 면 | 강한 대비·명확한 구획 |
| Corporate / Trust | 2-col 좌→우 (30:70) | 면 | 안정적·예측 가능 |
| Minimal / Luxury | 1-col 전면 또는 여백 분할 | 여백 | 공간 자체가 메시지 |
| Energetic / Magazine | 사선 또는 역순 2-col | 면+clip | 역동성·방향감 |

## 6. 쇼케이스 워크플로

### 6.1 Cover 3안 + 본문 2안 = 5장 (모든 덱 의무)

**왜 커버가 본문보다 많나**: 커버는 첫인상과 전체 톤을 결정하는 **가장 중요한 슬라이드**다. 본문 톤은 한 번 정하면 13장에 일관 적용되지만, 커버는 레이아웃·비율·경계 표현 조합에 따라 인상이 크게 갈린다. 본문 2안은 **그리드 다양성만 검증**하는 용도다.

### 6.2 8단계

```
1. Cover 3안 — 3축 조합이 모두 다른 변형 3개
   예: A(2-col 40:60 면) / B(1-col 전면 여백) / C(사선 clip-path 면+선)
2. 본문 2안 — 시각적으로 가장 다른 2장 (표 + 타임라인 / 카드그리드 + Statement)
3. 5장 완성도 있게 생성 → showcase.html + 개별 스크린샷
4. 5-up grid HTML 생성 → showcase-grid.html
   ⚠️ iframe 금지 (file:// cross-origin으로 contentDocument 접근 차단)
   → .slide 5개를 grid HTML에 직접 박고 transform:scale()로 축소
   → 위 row 3열(Cover A/B/C) + 아래 row 2열(Body 1/2)
5. 풀페이지 스크린샷 (showcase-grid.png)
6. 브라우저 자동 실행 (필수)
   Windows: cmd.exe //c start "" "{path}/showcase-grid.html"
7. 사용자 컨펌 요청 — "Cover 어느 안?" + "본문 톤 OK?"
8. NG → 5장 재작업·재컨펌 (재작업 시에도 브라우저 자동 오픈 의무)
   OK → 선택 Cover로 전체 N장 생성
```

### 6.3 컨펌 = 확정 (재작업 금지)

사용자가 컨펌한 쇼케이스 슬라이드는 본 작업에서 **HTML·CSS 그대로 이식**한다.
- 선택 Cover → S1으로 그대로
- Body-1 / Body-2 → 매핑된 슬라이드로 그대로
- **나머지 슬라이드만 신규 생성**
- 카운터(N/13) 같은 메타 정보만 자동 정정 OK

**이유**: 다시 만들면 (a) 사용자가 본 것과 미세하게 달라지고 (b) 컨펌이 무의미해지고 (c) 재작업 비용만 든다.

### 6.4 본 작업 진입 전 자가 점검 (하나라도 ❌면 진입 금지)

```
□ ① 쇼케이스 산출물이 디스크에 존재하는가?
     (showcase.html, showcase-grid.html, slide-01~05.png, showcase-grid.png)
□ ② 사용자 컨펌 응답이 직전 메시지(또는 BRIEF)에 명시되어 있는가?
     ⚠️ "디자인 컨셉을 직접 줬다" ≠ 쇼케이스 컨펌. 별개 절차다.
□ ③ 컨펌된 Cover 안과 본문 안이 명확히 식별되는가?
     "그냥 진행해" 같은 모호한 응답이면 ❌ → 재컨펌
□ ④ 컨펌 산출물이 이식될 위치가 매핑되어 있는가?
□ ⑤ BRIEF에 "쇼케이스 생략" 지시가 있어도 무시했는가?
```
**이건 메인이 잘못된 BRIEF로 호출했을 때의 마지막 안전망이다.** 메인이 "13장 빌드해"라고 직접 지시해도 하나라도 ❌면 거부한다.

### 6.5 산출물 페어 의무 (2차 호출)

| 파일 | 역할 |
|---|---|
| `deck.html` | 본 작업 N장 |
| `color-tuner.html` | 5개 토큰 인터랙티브 픽커 |

**한쪽만 만들면 위반이다.** 2차 호출 종료 직전 자기 체크.

### 6.6 브라우저 오픈 규칙

- **`color-tuner.html` 단 하나만 자동 오픈**
- **`deck.html` 자동 오픈 절대 금지** — deck.html은 진실 소스지만 사용자 인터랙션 surface가 아니다. color-tuner가 superset을 제공하므로 둘 다 열면 혼란만 준다
- "deck + tuner 통합 → 브라우저 실행" 같은 **모호한 narration도 금지** (둘 다 여는 결과를 부른다)

### 6.7 self-verification은 최대 2회

```
1. deck.html 빌드 + 전 슬라이드 스크린샷
2. self-review: 명백한 깨짐만 검출 → 1회 수정
3. 재검토 → 1회 더 수정 (최종)
4. 종료
```
**self-review 범위**: 텍스트 잘림 / 요소 겹침 / font 폴백 깨짐 **만**.
Hero 강도·시각 균형·색상 대비·5차원 품질·스타일 정체성은 **visual-refiner 영역**이다.

**실패 사례**: 2차 호출이 self-verification 루프로 **8분 이상** 소비하며 visual-refiner 영역까지 침범. → 최대 2회로 끊고 메인에 반환.

## 7. HTML 구조

### 7.1 필수 조건

- Tailwind CDN + Pretendard CDN (빌드 없이 열림)
- **전체 슬라이드 1개 파일**
- 키보드 네비 — `←` `→` `Space`
- 슬라이드 카운터 — 우하단 `N / Total`
- 스피커 노트 토글 — `S` 키
- 풀스크린 — `F` 키
- 16:9 고정 캔버스 + CSS scale
- 색상 토큰화 (`:root` 변수)

### 7.2 display는 CSS가 단독 관리

```html
<!-- ❌ inline display:flex가 CSS display:none을 덮어써 모든 슬라이드가 동시에 보인다 -->
<section class="slide active" style="display:flex; flex-direction:row;">

<!-- ✅ display는 .slide / .slide.active가 관리 -->
<section class="slide active" style="flex-direction:row;">
```
- `flex-direction`·`align-items`·`justify-content`는 inline 유지 OK
- **`display`만은 절대 inline에 쓰지 않는다**
- ID 컨벤션 `id="s1"`, `id="s2"`… / 첫 슬라이드만 `class="slide active"`

### 7.3 JS 스케일링 (필수 패턴)

```javascript
let cur = 1;
const total = [슬라이드 수];
const lightSlides = new Set([밝은 배경 슬라이드 번호들]);

function scale() {
  const deck = document.getElementById('deck');
  const s = Math.min(window.innerWidth/1280, window.innerHeight/720);
  const ox = (window.innerWidth - 1280*s)/2;
  const oy = (window.innerHeight - 720*s)/2;
  deck.style.transform = `translate(${ox}px,${oy}px) scale(${s})`;
}
function go(n) {
  document.getElementById('s'+cur).classList.remove('active');
  cur = Math.max(1, Math.min(n, total));
  document.getElementById('s'+cur).classList.add('active');
  const el = document.getElementById('counter');
  el.textContent = cur + ' / ' + total;
  el.className = lightSlides.has(cur) ? 'dark' : '';
}
```
카운터 톤은 `lightSlides` Set에 밝은 배경 번호를 등록하면 `#counter.dark`가 자동 적용된다.

### 7.4 Color Tuner — 템플릿만 사용

**직접 작성 금지.** `references/templates/color-tuner.template.html`의 placeholder만 치환한다. (매 호출마다 미세하게 달라지는 위험 차단)

**🔴 TOKEN USAGE AUDIT (필수)**: picker에는 **실제로 사용되는 토큰만** 노출한다.
```bash
grep -oE 'var\(--[a-z0-9-]+\)' deck.html
```
- `var()` 호출이 0건인 토큰은 picker에서 제외 — **dead token을 노출하면 사용자가 바꿔도 시각 변화가 없다**
- 같은 값으로 alias된 토큰(`--c-accent` = `--c-primary`)은 1개로 병합

**실패 사례 (2026-04-29 test03)** — 사용자 표현: **"랜더마이즈 해도... 변화가 없음"**

## 8. 이미지 / Placeholder


### 8.3 placeholder 마크업

```html
<div class="image-slot empty"
     data-slot-id="{slot_id}"
     data-slot-type="{photo|illust}"

     data-slot-ratio="{16:9|4:3|1:1}"
     data-slot-status="placeholder">

</div>
```
`data-*` 5개는 이미지 패스가 매칭하는 키라 **전부 필수**다. CSS는 `rgba` 금지 · `color-mix` 의무.

## 9. Anti-slop 금지 목록

```
❌ 무지개 그라데이션 배경 (보라→분홍→파랑 전체화면)
❌ 둥근 카드 + 좌측 border accent   ← AI 카드 시그니처
     .card { border-radius:12px; border-left:4px solid #hex; }
❌ UI 이모지 장식 (🚀 ⚡ ✨ 🎯)  → 아이콘 필요 시 Lucide/Heroicons
❌ SVG로 그린 인물·장면·기기 imagery → 회색 placeholder
❌ 조작된 통계 수치 ("10,000+ 고객" 등 근거 없는 숫자)
❌ 가짜 고객 후기
❌ 금지 폰트 (Inter/Roboto/Arial/Helvetica/Space Grotesk/Fraunces)
❌ 라이트 스타일에 "있어 보여서" 다크 커버 삽입
```

## 10. 커버 전용 규칙

### 10.1 텍스트 요소는 최대 2개

```
허용:
  ① 덱 제목 (필수)
  ② 서브타이틀 또는 날짜/발표자 중 1개 (선택)

금지:
  × 회사명 + 제목 + 서브타이틀 + 날짜 + 발표자 동시 나열
  × 로고 + 배경 설명 텍스트 병행
  × 3개 이상의 독립 텍스트 블록
```

### 10.2 커버 Anti-Pattern (절대 금지)

```
1. 메타 row 나열 금지
   ❌ "사업예산 / 사업기간 / 제안사" 같은 3~4칸 정보 테이블
   ❌ "5.59B KRW · 210 Days · RELIABLE" 형태 푸터
   ✅ 날짜 1줄 또는 발표자 1줄만 (서브타이틀 역할)

2. 4블록 구조 금지
   ❌ 태그 + 제목 + 서브타이틀 + 메타row = 4개 독립 블록
   ✅ [장식] + 제목                      = 1블록
   ✅ [장식] + 제목 + 서브타이틀           = 2블록 (최대)
```

### 10.3 이미지·장식 역할

- 이미지는 **정보 전달 주체가 아니라 비주얼 배경**. 도표·텍스트·제품 화면·데이터를 담으면 안 된다. 목적은 대기감·분위기다
- **데이터·숫자 카드는 장식이 아니다 → 커버에 금지.** 수치는 본문 슬라이드에서
- **타이틀 주목도 > 장식 주목도** (절대 원칙). 도형이 커 보이면 opacity를 낮추거나 blur를 더한다
- 좌우 배치 시 **동등한 focal point 2개 금지**

### 10.4 커버 생성 전 체크

```
□ 텍스트 블록 ≤ 2개인가?
□ 메타 row(정보 나열) 없는가?
□ 이미지가 정보를 담지 않고 배경 역할만 하는가?
□ 장식이 타이틀보다 눈에 덜 띄는가?
□ 스타일의 base theme(라이트/다크)를 그대로 쓰는가?
□ 1280×720 캔버스인가?
```

## 11. 자가검수 체크리스트

### 11.1 쇼케이스 자가검수 (스크린샷 **전**에 SDA가 직접)

> HTML 저장 직후, 스크린샷을 찍기 **전에** **실제 코드 분석으로 카운트**한다. 직관 판정·"1세트로 묶었다"는 핑계 금지.

```
[커버 — 시각적으로 분리된 모든 영역을 카운트]
□ 텍스트 블록 ≤ 2개?
   카운트 예: 워드마크(1) + 메인타이틀(2) + 푸터메타(3) → 3블록 ❌
□ 메타 row 0개?  (.cover-meta, "예산·기간·등급" 나열 모두 금지)
□ 우측 비주얼 패널이 정보(차트·수치 카드·UI)를 담지 않는가?
□ 캔버스 1280×720?

[Anti-slop]
□ 금지 폰트 미사용?
□ 무지개 그라데이션 없음?
□ 둥근 카드 + border-left accent 없음?
□ SVG imagery 대신 placeholder?

[색상·타이포]
□ 60-30-10 준수?
□ Accent ≤ 3곳/슬라이드?
□ 폰트 계층 3:2:1?
□ 본문 최소 16px?
□ 인라인 rgba() 0건?  ← grep으로 카운트, 반드시 0
□ :root alpha 토큰 전부 color-mix 기반?

[본문 vertical 분포]
□ justify-content:space-between 또는 3-zone 분배 적용?
□ 콘텐츠가 상단에 50% 이상 쏠려있지 않은가?

[inverse panel 텍스트]
□ 하드코딩 panel 위 텍스트가 var(--c-text)를 그대로 쓰지 않는가?
□ panel과 그 위 텍스트의 anchor가 일관되는가?
```

**처리**: 하나라도 ✗이면 **즉시 재빌드**. 스크린샷·사용자 보고 모두 금지. 통과 후에만 스크린샷.
보고할 땐 **실제 카운트 숫자**로 명시한다 ("텍스트 블록: 2개 ✓").

### 11.2 생성 전 자기 체크

```
[베리에이션]
□ 각 슬라이드의 Expression / Proportion / Padding을 결정했는가?
□ panel Expression이 전체의 40% 이하인가?
□ 연속 2장 동일 Expression이 없는가?

[공통]
□ 디자인 시스템을 사용자에게 선언하고 확인받았는가?
□ 슬라이드당 핵심 메시지 1개인가?
□ 커버 텍스트 요소 ≤ 2개인가?
□ Visual ≥ 60%인가? Text ≤ 35%인가?
□ 폰트 계층이 3:2:1로 눈에 보이게 차이나는가?
□ 본문 ≥ 16px, 제목 ≥ 40px인가?
□ 배경 타입에 맞는 Accent Hex인가? (Warm→Red/Orange, Cool→Orange/Teal)
□ 스크린샷으로 실제 가독성을 눈으로 확인했는가? (썸네일에서도 읽히는가)
```

## 12. 레이아웃 카탈로그

## 13. 콘텐츠 재편성 (원본이 있을 때)

> **한 슬라이드 = 핵심 메시지 1개**

| 진단 신호 | 처방 |
|---|---|
| 한 페이지에 주제 3개 이상 | 슬라이드 분리 |
| 글머리 기호 5개 이상 | 상위 3개만 남기고 나머지는 스피커 노트로 |
| 설명 문장이 2줄 이상 | 핵심 키워드(**5~10자**)만 추출, 문장은 스피커 노트 |
| 데이터와 배경 설명이 혼재 | 배경(스토리) / 데이터 슬라이드 분리 |
| 결론이 마지막에 묻힘 | 결론을 앞으로 (**BLUF 구조**) |

**HTML 생성 전 Step 1-E 필수**: 각 슬라이드의 **실제 텍스트**를 명시하고 사용자 확인을 받는다. 추상적 설명 금지 — "다이어그램 3개" ❌ / "에이전트 카드: slide-deck-agent / slide-qa-agent / SKILL.md" ✅. 숫자·지표는 **실제 값 확정** (임의 생성 금지).

## 부록. 실패 사례 모음 (전부 실제로 터진 것)

| 실패 | 결과 |
|---|---|
| 쇼케이스 없이 본 작업 직행 | 사용자가 못 본 디자인이 확정 → 컨펌 무의미 + 재작업 |
| Color Tuner에 dead token 노출 | 사용자: **"랜더마이즈 해도 변화가 없음"** |
| 인라인 `rgba(255,255,255,0.78)` | 라이트 팔레트 전환 시 흰 배경 위 흰 글씨 → **가독성 0** |
| 하드코딩 dark panel 위 `var(--c-text)` | 라이트 팔레트에서 텍스트가 panel과 동색 → **invisible** |
| 2차 호출 self-verification 8분+ | visual-refiner 영역 침범 → 최대 2회로 제한 |
| deck.html + tuner 동시 오픈 | 사용자 혼란 → tuner 하나만 |
| showcase-grid에 iframe 사용 | `file://` cross-origin으로 접근 차단 → 렌더 실패 |
| `.slide`에 inline `display:flex` | CSS `display:none`을 덮어써 **모든 슬라이드가 동시에 보임** |
| 카드 height에 CSS Grid | grid item에서 `height:100%` 미상속 → **height 0** |
| 1920×1080 캔버스 | PPTX 변환 시 폰트가 작아 보임 |
| PPTX 토큰 밖 line-height | 한국어 자동 leading으로 **마침표↔다음 줄 충돌**, hero가 footer 침범 |
| 라이트 스타일에 다크 커버 삽입 | anti-slop |
| 커버에 데이터 카드 배치 | 커버는 장식만 — 수치는 본문에서 |
| 본문 상단 stacking (`align-items:start` + gap) | 하단 무인지대 → 3-zone 분배 필요 |
| Timeline 하단에 `airy` 패딩 | 노드 간격이 벌어져 **선이 단조로워짐** |
