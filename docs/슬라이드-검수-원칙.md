## 검수는 2단이다 (역할 분리)

검수를 한 덩어리로 하지 않는다. **코드로 판정 가능한 것**과 **눈으로만 판정 가능한 것**을 나눈다.

| slide-qa-agent (코드 검수) | visual-refiner (시각 검수) |
|---|---|
| HTML 구조 정합성 | 시각 품질·디자인 심미성 |
| 폰트 렌더링 (폴백 버그) | 색상 대비율 |
| CSS display 패턴 | 시각 계층 · Hero 명확성 |
| 카운터 시스템 정확성 | 여백 균형 |
| 그리드 다양성 | 스타일 정체성 반영도 |
| 공간 문법 다양성 | 스크린샷 기반 검사 |

**실행 순서**: slide-qa-agent → 수정 완료 → visual-refiner

**왜 나누나**: 코드 분석은 정량 룰이라 자동 판정·자동 수정이 가능하고, 시각 평가는 정성 판단이라 사람 눈(또는 스크린샷을 본 LLM)이 필요하다. 섞으면 둘 다 얕아진다.

**PPTX 호환 검사는 두 에이전트 범위 밖**이다. `slide-pptx-agent`가 변환 시점에 자동 처리(gradient → solid, div/span → p 등)하므로, HTML 단계에서는 gradient·복합 마크업을 자유롭게 써도 된다.

## 1.1 Tier 체계 — 무엇을 자동으로 고치고 무엇을 물어보나

## 1.2 침묵 금지 (Progress Narration 의무)

코드 분석은 길고, 메인 스레드는 sub-agent 내부를 보지 못한다. **Tier 진입·완료마다 한 줄씩** 출력한다.

```
🔍 Slide QA 시작 — [파일명] / [N]장

[Tier 1] 진입 — Silent Auto-fix (A5/A6/A7/A8/A9/B1/D1)
[Tier 1] 완료 — 자동 수정 N건 (A5 ×3, B1 ×2, D1 ×1)
[Tier 2] 진입 — Blocking (A1/A2/A3/A4/B2/G3/G4/G5)
[Tier 2] 완료 — 위반 N건
[Tier 3] 진입 — Quality Warning (C1/C2/D2/D3/E1/E2/E3/G1/G2)
[Tier 3] 완료 — 경고 N건
[Tier 4] 진입 — Design Discussion (H1/H2/H3)
[Tier 4] 완료 — 정보 N건
[통합 리포트] ↓
```

**한 마디라도 침묵하면 사용자는 "멈춘 것"으로 인식한다.**

### Group B — 한국어 폰트 렌더링 (2개)

| # | 항목 | 통과 기준 | Tier |
|---|---|---|---|
| **B1** | 한국어에 비한국어 폰트 금지 | 한국어 텍스트를 담은 요소에 한국 글리프 없는 폰트를 직접 지정하지 않음 | 1 |
| **B2** | 한국어 폰트 로딩 | 한국어 사용 시 Pretendard CDN 존재 | 2 |

**블랙리스트 (한국 글리프 없음 — 지정 시 시스템 폰트로 폴백되어 버그)**
```
Clash Display, Satoshi, Space Grotesk, Playfair Display,
Cormorant, Fraunces, Canela, Editorial New, Neue Haas Grotesk,
Plus Jakarta Sans (Latin-only), DM Serif Display
```

**감지 방법**: `font-family:'Clash Display'` 같은 지정 + **해당 태그 안에 한국어 텍스트가 실제로 있는지 교차 확인**. (영문 전용 요소에 쓰는 건 정상)

**올바른 스택**
```css
/* 헤딩도 한국어면 Pretendard 필수 */
font-family: 'Pretendard', sans-serif;

/* 영문 Display + 한국어 혼합 */
font-family: 'Clash Display', 'Pretendard', sans-serif;
/* 단 이건 폴백 의존이므로, 한국어가 주를 이루면 Pretendard 단독 지정을 권장 */
```

**자동 수정**: 한국어 포함 요소의 비한국어 `font-family` → `'Pretendard',sans-serif`로 교체.

### Group C — Letter-spacing (2개)

| # | 항목 | 통과 기준 | Tier |
|---|---|---|---|
| **C1** | 대형 텍스트 자간 | `font-size` **40px 이상** 요소에 **음수 letter-spacing 없음** | 3 |
| **C2** | 의도적 타이트닝 예외 | `-0.01em` 이하(절댓값 작은 값)는 ❌가 아닌 ⚠️ 경고만 | 3 |

**근거**: Clash Display·Satoshi·Space Grotesk 등 디스플레이 폰트는 **이미 자체 자간이 좁게 설계**되어 있다. 여기에 음수 letter-spacing을 더하면 글자가 충돌한다. 기본값(0 또는 속성 생략)이 최적이다.

**예외 허용**: 소형 eyebrow 레이블·태그류의 **양수 letter-spacing (0.08em~0.20em)**은 정상.

### Group D — 카운터 시스템 (3개)

| # | 항목 | 통과 기준 | Tier |
|---|---|---|---|
| **D1** | `#counter.dark` 규칙 존재 | CSS에 `#counter.dark{color:...}` 존재 | 1 |
| **D2** | lightSlides ↔ 실제 배경 일치 | lightSlides에 든 슬라이드의 **카운터 위치 영역** 배경이 실제로 밝은지 | 3 |
| **D3** | 전체 다크 덱 예외 | 전부 어두우면 lightSlides가 비어도 OK. 단 **밝은 슬라이드가 1개라도 있으면 반드시 포함** | 3 |

**D2가 까다로운 이유 — 혼합 배경 슬라이드**

카운터는 `position:fixed; right:20~30px; bottom:20px`에 있으므로 **슬라이드 오른쪽 영역** 배경색만 영향을 준다.

```
2-col 커버 (왼쪽 밝음 / 오른쪽 어두움):
  → 카운터는 오른쪽(어두운 배경) 위에 놓임
  → lightSlides에 넣으면 .dark 적용 → 검정 글자 on 검정 배경 = 안 보임
  → 올바른 분류: lightSlides에서 제외 (카운터 white 유지)

판단 기준:
  - 오른쪽 패널이 #888 이하 밝기(어두움)  → lightSlides 제외
  - 전체가 #ccc 이상 밝기(크림·흰색)      → lightSlides 포함
  - 오른쪽이 accent 색(빨강·코랄 등 중간톤) → ⚠️ 경고, 직접 판단
```

### Group H — 공간 문법 다양성 (3개, 전부 Tier 4)

**왜 있나**: 그리드(레이아웃)가 달라도 **공간을 나누는 방식**이 같으면 덱이 통째로 똑같아 보인다. "모든 슬라이드가 배경색 채운 직사각형 패널로 분할" = 패널 채움 과잉. 스타일마다 기대하는 공간 문법이 다르다.

**공간 문법 4유형**

| 유형 | 정의 | 대표 스타일 |
|---|---|---|
| **패널 채움** | 직계 div가 배경색으로 공간을 채워 분리 | Neo-Brutalism, Raw Form |
| **타이포 주도** | 배경 패널 없이 텍스트 크기·무게가 공간을 구성 | Swiss Style, Minimalist |
| **플로팅 컨텐츠** | 콘텐츠가 단일 dark ground 위에 떠 있음 | Midnight Editorial |
| **룰 분리** | 배경색 없이 얇은 선(1~2px)만으로 구획 | Swiss, Newsprint |

| # | 항목 | 통과 기준 |
|---|---|---|
| **H1** | 패널 채움 비율 | 스타일별 기대값 초과 시 ⚠️/❌ |
| **H2** | S2 커버 유사성 | S2가 **64px+ 타이포 + 다크 bg + 1col**이면 S1(커버)과 공간 문법 중복 |
| **H3** | 스타일별 기대 공간 문법 | 아래 표와 실제 구현 대조 |

**H3 스타일별 기대값**

| 스타일 감지 키워드 | 기대 공간 문법 | 패널 채움 허용 비율 |
|---|---|---|
| Swiss / Inter 900 / #FF3000 | 타이포 주도 + 룰 분리 | **≤ 40%** |
| Midnight / Satoshi / #FF6B50 + all-dark | 플로팅 컨텐츠 | **≤ 40%** |
| Neo-Brutalism / Space Grotesk / shadow-hard | 패널 채움 허용 | **100%** |
| Raw Form / Clash Display / #E4E2DD | 패널 채움 허용 | **100%** |
| Minimalist / echo-minimalist | 타이포 주도 | **≤ 20%** |

**패널 채움 슬라이드 감지**
```
1. section의 직계 자식 div 중 flex 담당(flex: 또는 flex-direction:) 추출
2. 그중 background: 가진 것 카운트
3. (background 보유 수) / (전체 flex 자식 수) ≥ 0.8  → 이 슬라이드 = 패널 채움
4. (패널 채움 슬라이드 수) / (전체 슬라이드 수) = 덱의 패널 채움 비율
```

**자동 수정 없음.** 문제 슬라이드와 방향만 제시한다.
- 패널 채움 과잉 → 자식 div의 `background:` 제거, 얇은 border로 대체
- S2 커버 유사 → S2 배경을 밝게 전환하거나 레이아웃 방식 변경

## 1.5 리포트 형식

```

❌ 필수 수정 (Tier 2): N건
   - A1: 슬라이드 ID s5 누락 → ⚠️ 수동 확인 필요
   - B2: Pretendard CDN 미로딩 → <link> 추가 필요

⚠️ 사용자 확인 (Tier 3): N건
   - C1: s2 음수 자간 (Clash Display는 자체 자간 좁음 — 의도면 유지)
   - E3: 1col-full 그리드 S2·S6·S10 3회 반복 — S6 변경 권장
   → 수정할까요?

📋 디자인 정보 (Tier 4):
   - H1: 패널 채움 38% (Swiss 기준 ≤40% — 적정)

━━━━━━━━━━━━━━━━
요약: ✅ 자동 N · ❌ 필수 N · ⚠️ 확인 N · 📋 정보 N
```

**원칙**: Tier 1은 한 줄 요약만. Tier 2·3은 **위반 항목만** 표시(PASS는 노이즈라 표시 안 함). Tier 4는 판단 정보만.

# 2부. 시각 검수 (visual-refiner)

## 2.1 🔴 절대 규칙 — 평가·제안만 한다, 고치지 않는다

**visual-refiner는 평가자다. 수정자가 아니다.**

| 허용 | 금지 |
|---|---|
| 코드 분석·시각 검사·5차원 채점·diff 형태의 **제안** | **Edit / Write 자율 호출** |
| 스크린샷 캡처 | 산출 HTML/CSS 직접 변경 |
| "이 부분을 이렇게 바꾸자" diff 블록 출력 | "수정했습니다 / 적용 완료" 사후 통보 |

**왜 이렇게 막았나**: 예전엔 visual-refiner가 자체 판단으로 자동 수정을 적용했는데, **사용자 동의 없이 산출물이 바뀌는 일**이 실제로 발생했다(2026-04-29 test03 검증). 그래서 수정 권한을 메인·사용자에게만 남겼다.

**예외 없음.** ❌이 0건이든 ⚠️만 있든, visual-refiner는 절대 직접 수정하지 않는다.

**적용 흐름**
```
visual-refiner: 제안 출력 → [종료]
       ↓
사용자 컨펌: 전부 적용 / 일부 선택 / 넘어가기 / 직접 수정안 제시
       ↓
메인: Edit tool로 적용 → 필요 시 visual-refiner 재호출해 재검증
```

## 2.2 실행 6단계

```
코드 분석 → 스크린샷 → 시각 검사 → 5차원 평가 → 수정 제안(diff) → [종료·컨펌 대기]
```
visual-refiner는 **6단계에서 끝난다.** 컨펌과 적용은 메인 책임이다.

**메인이 직접 take_screenshot으로 자체 QA 처리하는 것 금지** — sub-agent 시스템 프롬프트로 동작해야 검증 깊이가 나온다.

## 2.3 1단계 — 코드 분석

| 항목 | 기준 |
|---|---|
| 타이포 스케일 | h1 > h2 > h3, 인접 비율 **1.2× 이상** |
| 스페이싱 | **8px 배수** |
| 금지 폰트 | Inter / Roboto / Arial / Space Grotesk 없음 |
| Anti-slop | 무지개 그라데이션, border-left accent 카드 없음 (스타일 미지정 시) |

**스타일별 Anti-slop 예외** — 해당 스타일을 골랐으면 그 특징은 검사 제외

| 스타일 | 예외 항목 |
|---|---|
| cyberpunk, vaporwave, neon-velocity, acid-graphic | 네온 글로우, 크로매틱 어버레이션, box-shadow 중첩 |
| minimalist-*, swiss-style, echo-minimalist | Hero 40% 기준 (균등 계층이 의도) |
| maximalism-dopamine, hyper-saturated-fluid | 다중 accent (5색 동등 강도가 의도) |
| terminal-cli, win98-retro | 픽셀 폰트, low-contrast 배경 |

## 2.4 2단계 — 스크린샷 시각 QA

**캡처 규칙**: 모든 슬라이드를 `take_screenshot(filePath: "_test/outputs/[name]/refiner-s{N}.png")`로 **파일 저장 후 Read**. **vision attach(filePath 미지정) 금지** — 다른 에이전트 공유·아카이브·핸드오프가 안 된다.

**눈으로 판단하는 7개 항목**

| 항목 | 판단 기준 |
|---|---|
| 가독성 | 썸네일 크기(절반)에서도 텍스트가 읽히는가 |
| 텍스트 크리핑 | 텍스트가 컨테이너 밖으로 잘리는가 |
| 레이아웃 붕괴 | 요소가 의도한 위치에 있는가, 겹침 없는가 |
| Hero 명확성 | 시선이 가장 먼저 가는 요소가 **1개** 명확한가 |
| 여백 분포 | 한쪽으로 쏠리지 않았는가 |
| 색상 대비 | 배경과 텍스트 대비가 육안으로 충분한가 |
| 스타일 정체성 | 고른 스타일의 특징이 실제로 보이는가 |

> **슬라이드는 스크롤이 없는 단일 화면**이므로, 텍스트 크리핑·균형 기준을 웹보다 **1단계 엄격하게** 본다.

**균형 체크리스트 (수식 대신 질문으로)**
```
□ 화면을 절반으로 가렸을 때 (좌/우, 상/하) 각각 "뭔가 있다"는 느낌인가?
□ 시선이 자연스럽게 좌상→우하(또는 의도한 방향)로 흐르는가?
□ 한 요소가 "확실히 주인공"으로 보이는가?
□ 여백이 숨막히지 않고 "숨쉬는" 느낌인가? (전체의 25% 이상)
```

**자주 나오는 불균형 4패턴**

| 패턴 | 증상 | 처방 |
|---|---|---|
| 상단 과부하 | 상단 빽빽, 하단 텅 빔 | 하단에 카드·CTA 배치 |
| 좌측 편중 | 텍스트만 좌측, 우측은 여백 | 우측에 이미지·카드 추가 |
| 색상 클러스터 | accent가 한 구석에만 몰림 | 대각선으로 분산 |
| 빈 코너 증후군 | 특정 모서리만 완전히 빔 | 소형 장식 요소로 보완 |

## 2.5 시각 지배 계층 — "모두가 주인공이면 주인공이 없다"

모든 요소가 동등한 무게면 시선은 갈 곳을 잃는다. 한 화면엔 **명확한 주인공 1개**가 있어야 하고, 나머지는 조연·배경으로 종속되어야 한다.

| Tier | 시각 무게 비율 | 요소 | 허용 스타일 |
|---|---|---|---|
| **Hero (주인공)** | 전체의 **40~60%** | 메인 헤딩, 핵심 이미지, 대형 CTA | 최대 폰트, accent 색, border+shadow |
| **Supporting (조연)** | 각 **10~20%**, 2~4개 | 서브헤딩, 기능 카드, 설명 블록 | 중간 폰트, secondary/muted, 경량 shadow |
| **Background (배경)** | 각 **1~5%** | 장식 도형, dot 패턴, 구분선 | 저채도·저명도, border 없음 |

**Hero의 시각 무게 ≥ 조연 최고값의 2배.** 미달이면 ❌.

**주인공 부재 5패턴**
```
❌ 플랫 계층    : 모든 카드가 동일 크기·shadow·색 → Hero 없음
❌ 다중 주인공  : accent 요소가 4개 이상 → 시선 분산
❌ 장식의 반란  : 장식 요소 무게 합 > 조연 단일 요소 → 배경이 주인공 침범
❌ 전면 포화    : 휴식 공간 < 25% → 숨막힘
❌ 동일 강도 나열: 모든 텍스트 bold·모든 버튼 primary → 강조가 무의미
```

**계층 설계 5원칙**
1. **Hero를 먼저 정한다.** "이 화면에서 반드시 가져가야 할 것 1개"를 확정하기 전엔 레이아웃을 시작하지 않는다.
2. **조연은 Hero를 설명하거나 Hero로 이끈다.** Hero와 무관하면 배경으로 강등.
3. **나머지는 전부 배경이다.** 장식은 존재감을 주장하면 안 된다. dot·divider는 '없어도 읽히는' 수준으로.
4. **accent 색은 Hero에게만** (또는 Hero + 조연 1개). 모든 카드에 accent를 주면 Hero가 소멸한다. accent가 3개를 넘으면 가장 중요한 1개만 남기고 muted 처리.
5. **여백은 낭비가 아니라 호흡이다.** 여백 없이 채우면 Hero의 무게가 희석된다.

## 2.6 색상 대비 계산

```
상대 휘도 L = 0.2126×R + 0.7152×G + 0.0722×B  (sRGB 선형화 후)
대비율 = (밝은쪽 L + 0.05) / (어두운쪽 L + 0.05)

→ 4.5:1 미만 ❌ / UI 요소는 3:1 미만 ❌
```

## 2.7 5차원 품질 평가 (25점)

| 차원 | 배점 | 평가 질문 | 낮은 점수 징후 |
|---|---|---|---|
| ① 철학 일관성 | 1-5 | 고른 스타일의 핵심 정신이 실제로 반영됐나 | 스타일명만 있고 특징 없음 |
| ② 시각 계층 | 1-5 | 시선이 의도한 순서로 흐르나 | 모든 요소가 같은 크기·weight |
| ③ 디테일 실행 | 1-5 | 정렬·간격·색·폰트가 정밀한가 | 8px 배수 미준수, 색 일관성 없음 |
| ④ 기능성 | 1-5 | 모든 요소가 메시지 전달에 직결되나 | 장식이 콘텐츠를 방해 |
| ⑤ 창의성 | 1-5 | 규칙 안에서 독특한 표현이 있나 | generic AI 템플릿 느낌 |

**총점 판정**
- **20점 이상** → 핸드오프 가능
- **15~19점** → 1~2개 수정 후 가능
- **14점 이하** → 방향 재검토 권장

## 2.8 제안 출력 형식

```
🔍 QA 결과 — [레이아웃] / [스타일명]

[코드 분석]
✅ 타이포 스케일: h1(48) → h2(40) → h3(32) — 1.2× 통과
❌ 금지 폰트: Inter 사용 → Pretendard 교체 필요
⚠️ 스페이싱: padding 72px — 8px 배수 불일치 → 80px 권장

[시각 검사 — 스크린샷 기반]
✅ 가독성: 썸네일에서도 제목 읽힘
❌ 텍스트 크리핑: 3번 카드 본문 하단 잘림
✅ Hero 명확성: 좌측 메인 헤딩이 시선 앵커

총 ❌ 1개 / ⚠️ 2개

─────────────────────────────
📝 수정 제안 (diff) — 적용 권한은 사용자에게 있음
─────────────────────────────

[제안 #1] ❌ 금지 폰트 (Inter)
  파일: deck.html
  변경: --font-sans: 'Inter', sans-serif;
   →    --font-sans: 'Pretendard', system-ui, sans-serif;
  근거: Anti-slop 룰 — 한국어 콘텐츠 + 스타일 non-negotiable 폰트 미지정

[제안 #2] ❌ 텍스트 크리핑 (slide-3.card-body)
  변경: max-height: 180px;  →  (제거)
  근거: 본문 5줄이 max-height에 잘려 마지막 줄 가려짐

[제안 #3] ⚠️ 여백 분포
  → 레이아웃 구조 변경 필요. diff 단순 적용 대상 아님.

─────────────────────────────
🟦 사용자 컨펌 필요 — 다음 중 선택:
  (1) 전부 적용  (2) "1, 3만" 일부 선택
  (3) 넘어가기   (4) 직접 수정안 제시
```

**건수별 분기**
- ❌ 0 · ⚠️ 0 → `✅ QA 통과 — 제안 없음. 핸드오프 가능` (컨펌 게이트 스킵)
- ❌ 또는 ⚠️ 1개 이상 → 제안 출력 → 사용자 컨펌 → 메인이 적용
- **❌ 3개 이상** → 제안 + **"레이아웃 재설계 권장"** 메모. 작은 diff로는 해결 안 됨을 알린다.

## 2.9 재생성 권고 기준

아래는 diff로 못 고친다. **generator 재호출을 권한다.**
- 레이아웃 구조 자체가 바뀜 ("3-column → 2-column 전체")
- 디자인 시스템 전면 교체 ("다크모드 버전으로")
- 섹션 순서 대폭 변경
- ❌ 3개 이상 + 구조 결함이 근본 원인

## 2.10 침묵 금지 (Progress Narration)

```
🔍 VisualRefiner 시작 — [대상]
[코드 분석] 진입 → 완료 — ❌ N · ⚠️ N
[스크린샷 시각 QA] 진입 → 완료 — ❌ N · ⚠️ N
[5차원 품질 평가] 진입 → 완료 — 총점 N/25
[수정 제안] 작성 — diff N건 (적용 권한은 사용자에게)
[완료] 종합 리포트 + 제안 출력 ↓
```

**금지 문구**: `[자동 수정] 적용 N건` / `[적용 완료]` — visual-refiner에겐 적용 권한이 없다.
