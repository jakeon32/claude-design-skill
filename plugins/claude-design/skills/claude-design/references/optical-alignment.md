# 광학 정렬 (Optical Alignment)

> ## 수치 정렬이 아니라 시각적 밸런스 정렬이 중요하다.
>
> `left: 0`을 똑같이 줬는데 텍스트만 안으로 들어가 보인다면, 그건 버그가 아니라
> **인간의 눈이 픽셀이 아니라 시각 무게를 본다**는 뜻이다.

**2026-07-14 신설.** 그 전까지 이 스킬에는 광학 정렬이 "불릿 hanging" 한 줄뿐이었다.
아래 수치는 **추측이 아니라 Canvas에 렌더해 잉크 픽셀을 직접 센 실측값**이다
(`tools/optical_measure.js`).

---

## 1. 왜 어긋나 보이는가 — 눈은 "면"이 아니라 "획"을 본다

### 핵심 메커니즘

```
도형:    ████████   면 전체가 무겁다  → 경계 = 면의 끝
텍스트:  ┃규격은    첫 세로획 하나가 경계처럼 읽힌다 (나머지 공백은 무시됨)
```

**텍스트는 획 하나가 경계를 대표한다.** 그래서 그 획을 도형의 면과 **같은 x에 놓으면
획이 면보다 앞으로 튀어나온 것처럼** 보인다. 잉크의 시작점은 같은데도 그렇다.

→ **밀도가 낮을수록(획이 성길수록) 기준선에서 더 들여야 한다.**

### 시각 밀도 (실측)
```
솔리드 도형  ████████  밀도 1.00   ← 100% 채워짐. 기준선에 딱 붙인다
숫자         ▓▓▓▓▒▒▒▒  밀도 0.55
영문         ▓▓▓▒▒▒░░  밀도 0.49
소제목       ▓▓▒▒▒▒░░  밀도 0.42
대형 타이틀  ▒▒▒░░░░░  밀도 0.32
한글 본문    ▒▒░░░░░░  밀도 0.27   ← 가장 가볍다. 가장 많이 들인다
```

### 🔴 반대로 하기 쉽다 — 초판에서 실제로 그랬다

"잉크가 도형보다 안쪽에서 시작하니 밖으로 빼야 한다"는 계산은 **틀렸다.**
잉크 시작점을 맞추면 오히려 **더 어긋나 보인다**(실물 비교로 확인).

**측정은 원인을 알려주지만, 방향은 눈이 정한다.**
Canvas로 잰 잉크 밀도는 *얼마나* 보정할지를 알려줄 뿐,
*어느 쪽으로* 보정할지는 실제로 렌더해서 봐야 안다.

## 2. 실측값 (Canvas 잉크 픽셀 직접 측정)

| 개체 | 크기 | **광학 좌단** | **잉크 밀도** |
|---|---|---|---|
| **솔리드 도형 · 사진** | — | **0px** | **1.000** |
| 한글 타이틀 (800) | 48px | 2px | 0.324 |
| 한글 소제목 (700) | 34px | 2px | 0.420 |
| 한글 본문 (400) | 28px | 1px | **0.266** |
| 한글 본문 (400) | 19px | 1px | 0.255 |
| **영문 타이틀 (800)** | 48px | **4px** | 0.492 |
| 영문 라벨 (700) | 14px | 1px | 0.464 |
| 숫자 (800) | 32px | 1px | 0.547 |

### 참고: 광학 좌단은 크기에 비례하지 않는다
48px든 28px든 **1~2px로 거의 일정**하다. (영문만 예외적으로 4px — 라틴 글꼴은 베어링이 크다)
이 값은 *원인 진단*에는 쓸모 있지만 **보정값으로 그대로 쓰면 안 된다**(§1 참조).

## 3. 규칙 — 밀도가 낮을수록 마진을 더 준다

### 3-1. 기준선은 가장 밀도 높은 개체가 정한다

```
정렬 기준 (밀도 높은 쪽이 기준선)
  솔리드 도형 · 사진 · 색면   ← 기준선. 마진 0
  숫자 · 영문
  한글 제목
  한글 본문                   ← 가장 많이 들인다
```

**도형·사진이 있으면 그것이 기준선이다.** 텍스트를 도형에 맞추지, 도형을 텍스트에 맞추지 않는다.

### 3-2. 보정값 (실측 밀도 기반 — 밀도의 역수에 비례)

| 개체 | 잉크 밀도 | **마진** |
|---|---|---|
| 솔리드 도형 · 사진 | **1.00** | **0** ← 기준선 |
| 숫자 | 0.55 | **+0.02em** |
| 영문 | 0.49 | **+0.03em** |
| 소제목 | 0.42 | **+0.03em** |
| 대형 타이틀 | 0.32 | **+0.04em** |
| **한글 본문** | **0.27** | **+0.05em** ← 가장 많이 |

```css
/* 기준선 — 밀도 1.0 */
.solid, .photo, .color-block { margin-left: 0; }

/* 텍스트 — 밀도가 낮을수록 더 들인다 (양수) */
.num, .stat-num   { margin-left: 0.02em; }   /* 밀도 0.55 */
.en-text, .kicker { margin-left: 0.03em; }   /* 밀도 0.49 */
.subtitle         { margin-left: 0.03em; }   /* 밀도 0.42 */
.title            { margin-left: 0.04em; }   /* 밀도 0.32 */
.body, .kr-text   { margin-left: 0.05em; }   /* 밀도 0.27 — 가장 가볍다 */
```

**계수 유도**: `마진(em) ≈ 0.055 × (1 − 밀도)` 로 근사된다.
- 본문 0.27 → 0.055 × 0.73 = **0.040** (실사용 0.05)
- 타이틀 0.32 → 0.055 × 0.68 = **0.037** (실사용 0.04)
- 숫자 0.55 → 0.055 × 0.45 = **0.025** (실사용 0.02)

**em 단위를 쓰는 이유**: 폰트 크기가 바뀌어도 비율이 유지된다.

### 3-3. 예외 — 오히려 밖으로 빼야 하는 것

**행잉 펀추에이션(hanging punctuation)**은 방향이 반대다.
따옴표·불릿은 **거의 공백에 가까운 기호**라, 그것을 기준선에 맞추면 **본문 글자가 통째로 밀려 보인다.**
그래서 **기호를 좌측선 밖으로 걸고, 본문 글자를 기준선에 맞춘다.**

| 상황 | 처리 |
|---|---|
| **따옴표로 시작** (`“`, `「`) | 따옴표를 `margin-left: -0.4em`으로 **밖으로 건다** |
| **불릿·번호로 시작** | 마커를 `margin-left: -1.1em`으로 **본문 좌측선 밖**에 건다 |

> 헷갈리지 말 것: **본문 텍스트는 안으로(+), 앞에 붙는 기호는 밖으로(−).**
> 목적이 같다 — **글자의 시각적 좌단을 기준선에 맞추는 것.**

### 3-4. 우측 정렬

우측 정렬도 같은 원리로 **밀도가 낮을수록 안쪽으로** 들인다(`margin-right` 양수).

**단, 표의 숫자 우측 정렬에는 적용하지 마라.**
`tabular-nums`가 자릿수를 맞추고 있는데 여기에 광학 보정을 넣으면 **자릿수 정렬이 깨진다.**

## 4. 정직한 한계

**한글에서 효과는 미묘하다 (1~2px).** 영문은 확실하다 (4~5px). 그래도:

- **여백이 큰 화면일수록** 이 1~2px이 눈에 걸린다 (표지, 대형 타이틀, 좌우 분할)
- **도형·사진과 나란히 놓일 때만** 문제가 된다. 텍스트끼리는 서로 같은 조건이라 안 보인다
- **정보 밀도가 낮을수록** 도드라진다 (여백이 많으면 어긋남이 더 보인다 — C1 희소 슬라이드)

**→ 도형·사진과 텍스트가 같은 세로선에 놓이는 순간 적용한다.**
텍스트만 있는 슬라이드에는 필요 없다.

---

## 5. 🔴 이 문서가 한 번 틀렸던 기록

초판(2026-07-14)은 **보정 방향을 반대로 적었다.**
"잉크가 도형보다 안쪽에서 시작하니 밖으로(−) 빼야 한다"고 계산했는데,
실제로 렌더해 보니 **더 어긋나 보였다.**

원인: 잉크의 *시작점*을 맞추려 했지, 눈이 읽는 *경계*를 맞추지 않았다.
텍스트는 **획 하나가 경계를 대표**하므로, 획을 도형의 면에 맞추면 획이 튀어나와 보인다.

**교훈: 측정은 원인과 크기를 알려주지만, 방향은 반드시 실물로 확인한다.**
디자인 규범을 코드로 박을 때는 **렌더해서 눈으로 보는 단계를 건너뛰지 말 것.**

---

## 5. 폰트가 바뀌면 다시 잰다

```bash
node tools/optical_measure.js
```
Canvas에 실제로 렌더해서 **잉크 픽셀의 첫 x좌표**와 **밀도**를 측정한다.
폰트를 Pretendard에서 다른 것으로 바꾸면 베어링이 달라지므로 **반드시 재측정할 것.**
(측정에 시스템 폰트를 쓰므로, 실제 렌더에 쓸 폰트와 같아야 의미가 있다)
