# 광학 정렬 (Optical Alignment)

> ## 수치 정렬이 아니라 시각적 밸런스 정렬이 중요하다.
>
> `left: 0`을 똑같이 줬는데 텍스트만 안으로 들어가 보인다면, 그건 버그가 아니라
> **인간의 눈이 픽셀이 아니라 시각 무게를 본다**는 뜻이다.

**2026-07-14 신설.** 그 전까지 이 스킬에는 광학 정렬이 "불릿 hanging" 한 줄뿐이었다.
아래 수치는 **추측이 아니라 Canvas에 렌더해 잉크 픽셀을 직접 센 실측값**이다
(`tools/optical_measure.js`).

---

## 1. 왜 어긋나 보이는가 — 원인은 둘이다

### ① 사이드 베어링 (폰트에 내장된 여백)
글리프에는 좌우 여백이 이미 들어 있다. 텍스트 박스의 `left: 0`은 **잉크의 왼쪽이 아니다.**
도형은 `left: 0`이 곧 진짜 경계인데, 텍스트는 그보다 안쪽에서 시작한다.

### ② 시각 밀도 (같은 면적에 잉크가 얼마나 차 있나)
```
솔리드 도형  ████████  밀도 1.00   ← 100% 채워짐
숫자         ▓▓▓▓▒▒▒▒  밀도 0.55
소제목       ▓▓▒▒▒▒░░  밀도 0.42
대형 타이틀  ▒▒▒░░░░░  밀도 0.32
본문         ▒▒░░░░░░  밀도 0.27   ← 가장 가볍다
```
**밀도가 낮을수록 "가벼워" 보여서 기준선 안쪽으로 물러나 보인다.**
그러므로 **밀도가 낮은 개체일수록 기준선 밖으로 더 빼야** 시각적으로 맞는다.

---

## 2. 실측값 (Canvas 잉크 픽셀 직접 측정)

| 개체 | 크기 | **광학 좌단** | **잉크 밀도** |
|---|---|---|---|
| **솔리드 도형 · 사진** | — | **0px** | **1.000** |
| 한글 타이틀 (800) | 48px | 2px | 0.324 |
| 한글 소제목 (700) | 34px | 2px | 0.420 |
| 한글 본문 (400) | 28px | 1px | **0.266** |
| 한글 본문 (400) | 19px | 1px | 0.255 |
| **영문 타이틀 (800)** | 48px | **4px** | 0.492 |
| 영문 라벨 (700) | 14px | 1px | 0.464 |
| 숫자 (800) | 32px | 1px | 0.547 |

### 🔴 여기서 두 가지가 통념과 다르다

**① 광학 좌단은 크기에 비례하지 않는다.**
48px든 28px든 **1~2px로 거의 일정**하다. "큰 글씨일수록 em 비례로 더 빼야 한다"는 추측은 틀렸다.

**② 한글과 영문의 원인이 다르다.**
- **한글**: 사이드 베어링이 **거의 0**이다. 네모틀에 꽉 차는 글자이기 때문.
  → 치우쳐 보이는 원인은 **밀도**(0.27 = 솔리드의 **1/4 무게**)
- **영문**: 베어링이 한글의 **2배**(48px에서 4px). 라틴 글꼴은 좌우 여백이 크게 내장돼 있다.

## 3. 규칙

### 3-1. 기준선은 가장 밀도 높은 개체가 정한다

```
정렬 기준 우선순위 (높은 쪽이 기준선)
  솔리드 도형 · 사진 · 색면   ← 기준선. 보정 0
  라인 도형 · 테두리 박스
  숫자 · 대문자 영문
  한글 제목
  한글 본문                   ← 가장 많이 밖으로 뺀다
```

**도형·사진이 있으면 그것이 기준선이다.** 텍스트를 도형에 맞추지, 도형을 텍스트에 맞추지 않는다.

### 3-2. 보정값 (실측 기반)

```css
/* 기준선 */
.solid, .photo, .color-block { margin-left: 0; }

/* 텍스트 — 밀도·베어링에 따라 밖으로 */
.kr-text, .title, .body      { margin-left: -0.05em; }   /* 한글 */
.en-text, .en-title          { margin-left: -0.10em; }   /* 영문 — 베어링 2배 */
.num, .stat-num              { margin-left: -0.03em; }   /* 숫자 — 밀도 높음 */
.label, .kicker              { margin-left: -0.06em; }   /* mono 라벨(영문) */
```

**em 단위를 쓰는 이유**: 절대 px로 박으면 폰트 크기가 바뀔 때 다시 계산해야 한다.
실측상 보정량은 크기에 정확히 비례하진 않지만, **em이 실무상 가장 관리하기 쉽다**
(48px에서 -0.05em = -2.4px, 28px에서 -1.4px — 실측값 2px / 1px과 근사).

### 3-3. 추가 보정이 필요한 경우

| 상황 | 추가 보정 |
|---|---|
| **따옴표·괄호로 시작** (`“`, `(`, `「`) | **−0.4em** 더 (거의 공백이라 한 글자만큼 빈다) |
| **불릿·번호로 시작** | 마커를 `margin-left: -1.1em`으로 **본문 좌측선 밖**에 건다 (hanging) |
| **가벼운 글자로 시작** (`가`, `이`, `T`, `Y`) | 판단해서 −0.01~0.02em 더 |
| **무거운 글자로 시작** (`뭘`, `홍`, `M`, `W`) | 보정 줄임 |

### 3-4. 우측 정렬도 같다

우측 정렬 시에도 **잉크의 오른쪽 끝**이 기준이다. 특히 마침표·쉼표로 끝나면
그만큼 안쪽으로 들어가 보이므로 `margin-right`에 음수를 준다.
**숫자 우측 정렬(표)에서는 보정하지 마라** — `tabular-nums`가 자릿수를 맞추고 있고,
여기에 광학 보정을 넣으면 자릿수 정렬이 깨진다.

## 4. 정직한 한계

**한글에서 효과는 미묘하다 (1~2px).**
영문은 확실하다 (4~5px). 그래도:

- **여백이 큰 화면일수록** 이 1~2px이 눈에 걸린다 (표지, 대형 타이틀, 좌우 분할 레이아웃)
- **도형·사진과 나란히 놓일 때만** 문제가 된다. 텍스트끼리는 서로 같은 조건이라 안 보인다
- **정보 밀도가 낮을수록** 눈에 띈다 (여백이 많으면 어긋남이 도드라진다 — C1 희소 슬라이드)

**→ 도형·사진과 텍스트가 같은 세로선에 놓이는 순간, 이 규범을 적용한다.**
텍스트만 있는 슬라이드에는 굳이 필요 없다.

---

## 5. 폰트가 바뀌면 다시 잰다

```bash
node tools/optical_measure.js
```
Canvas에 실제로 렌더해서 **잉크 픽셀의 첫 x좌표**와 **밀도**를 측정한다.
폰트를 Pretendard에서 다른 것으로 바꾸면 베어링이 달라지므로 **반드시 재측정할 것.**
(측정에 시스템 폰트를 쓰므로, 실제 렌더에 쓸 폰트와 같아야 의미가 있다)
