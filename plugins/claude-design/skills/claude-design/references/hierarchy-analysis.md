# 위계 분석 (Hierarchy Analysis)

> ## 내용을 분석해서 위계를 파악해야 한다.
> 레이아웃을 먼저 고르고 내용을 끼워 넣는 것이 아니라,
> **내용의 위계가 레이아웃을 결정한다.**

**2026-07-14 신설.** 그 전까지 파이프라인에는 위계를 정의하는 단계가 **없었다.**
AI가 "이건 제목, 이건 본문" 정도로만 뭉뚱그렸고, 그래서 결과가 **워드 문서처럼** 나왔다.
시각 위계가 2단계(볼드 + muted)뿐이라 **눈이 착지할 지점이 없었다.**

---

## 0. 파이프라인에서의 위치

```
내용문서
  ↓
① 위계 인벤토리   — 모든 텍스트 조각을 층(L0~L6)으로 태깅   ← 이 문서
  ↓
② 밀도 집계       — 층별 개수·분량 → C1~C4 판정            (density-rules.md §4)
  ↓
③ 레이아웃 설계   — 위계 분포가 레이아웃을 결정             ← 이 문서 §3
  ↓
④ 렌더 → 린트
```

**②를 하기 전에 ①을 해야 한다.** 무엇이 몇 개인지 알아야 밀도를 셀 수 있다.

## 1. 위계 층 정의

| 층 | 이름 | 역할 | 개수 | 시각 사양 (D2 기준) |
|---|---|---|---|---|
| **L0** | Kicker | 섹션 라벨 · 카테고리 | 0~1 | mono 13px / 700 / tracking .16em / accent |
| **L1** | **Assertion** | **슬라이드의 결론** | **정확히 1** | 44px / 800 / letter-spacing −.02em |
| **L2** | Lead | 결론 부연 (한 줄) | 0~1 | 26px / 400 / muted |
| **L3** | Support | 근거 제목 | 2~4 | 24px / 700 |
| **L4** | Detail | 근거 설명 | L3당 0~1 | 19px / 400 / muted |
| **L5** | **Figure** | **수치 강조** | 0~4 | **64px / 800 / accent** ← 눈이 착지하는 지점 |
| **L6** | Meta | 출처 · 페이지 번호 | 0~2 | mono 12px / muted |

### 규칙

1. **L1은 정확히 하나다.** 두 개면 슬라이드가 두 장이어야 한다.
2. **위계는 5~6층까지 쓴다.** ← 🔴 2026-07-14 정정
3. **L5(수치)는 강력하다.** 있으면 반드시 시각적 주인공으로 쓴다.
   본문보다 **1.6~2.5배** 크게. 없는데 억지로 만들지 말 것.
4. **L3는 2~4개.** 5개 이상이면 분할 신호(density-rules §5 STEP 2).

> ### 🔴 초판의 "최대 4층"은 틀렸다 — 실측으로 정정
>
> 초판에 **"한 슬라이드에 위계는 최대 4층"**이라고 근거 없이 보수적으로 박았다.
> **BCG 실제 컨설팅 덱 112장을 측정하니 위계가 5~6층이었다** (중앙값 5층).
> 제목/본문 크기비도 **2.00배**로 일정했다.
>
> | 항목 | BCG 실측 (112장) |
> |---|---|
> | 위계 층수 | **5~6층** (중앙값 5) |
> | 제목/본문 크기비 | **2.00배** |
> | 색 종류 | 3~4개 |
> | 텍스트 블록 | 7~22개 (중앙값 13) |
>
> **레퍼런스가 내 규범을 반박했다.** 머릿속에서 만든 상한을 실물이 뒤집은 사례다.
> → 위계는 **필요하면 6층까지** 쓴다. 다만 **accent 색은 여전히 L0·L5에만**
>   (색이 3~4개를 넘으면 강조가 죽는다 — 이건 BCG도 지킨다).

## 2. 위계 인벤토리 작성법

내용문서를 읽고 **모든 텍스트 조각을 층으로 태깅**한다. 예:

```
원문:
  "우리 스킬에는 표 템플릿이 0개였고 도해도 0개였다. 카탈로그는 있다고
   등재해놓고 실체가 없었다. 리서치로 표 3종·도해 5종을 신설했고,
   차트는 값→픽셀 환산이 없어 눈대중으로 그리고 있었다."

인벤토리:
  L0  진단
  L1  카탈로그가 없는 템플릿을 있다고 등재하고 있었다     ← 결론
  L2  취약한 게 아니라 잘못된 지도를 준 것이다             ← 부연
  L5  0 / 0 / 4                                          ← 수치 (표·도해·죽은링크)
  L3  표 템플릿 0개        L4  카테고리 자체가 없었다
  L3  도해 템플릿 0개      L4  Venn은 등재됐지만 실체가 없었다
  L3  차트 눈대중 렌더     L4  값→픽셀 환산 규칙이 없었다
  L6  claude-design v1.0 실측
```

### 태깅 체크리스트
- [ ] **L1이 하나인가?** (결론이 두 개면 슬라이드를 쪼갠다)
- [ ] L1이 **주제가 아니라 주장**인가? ("표 현황" ✕ → "표 템플릿이 0개였다" ○)
- [ ] **L5(수치)를 놓치지 않았는가?** 숫자는 대부분 L5로 승격할 수 있다
- [ ] L3가 2~4개인가?
- [ ] L4 없이 L3만 있어도 이해되는가? (그러면 L4는 지운다 — coherence d=0.86)

## 2-5. ★ 관계 분석 — 위계만으로는 부족하다

> **관계가 있는 내용은 서로 연결해서 볼 수 있을 만큼 가까워야 한다.**
> 무엇이 그룹인지만이 아니라, **그룹끼리 어떤 관계인지**까지 설계해야 한다.

위계 태깅이 끝나면 **관계를 판정한다.** 이걸 건너뛰면
**대응하는 것을 좌우로 갈라놓거나, 무관한 것을 나란히 놓아 오독을 유발한다.**

### ① L5(수치)와 L3(근거)의 대응 관계

| 관계 | 배치 |
|---|---|
| **1:1 대응** | **같은 행에 붙인다. 좌우 분리 금지.** |
| | `[0]  표 템플릿` / `카테고리 자체가 없었다` |
| **독립** (전체 요약) | 좌측 열로 분리 가능 |
| | 좌: 총계 3개 · 우: 상세 항목들 |
| **부분 대응** | 대응하는 것만 붙이고 나머지는 따로. **억지로 개수를 맞추지 말 것** |

> 🔴 **실제로 저지른 실수**: 좌측에 `0 / 0 / 4`, 우측에 `표 / 도해 / 차트`를 나란히 놨는데
> **세 번째가 대응하지 않았다**("4=죽은 링크"와 "차트 눈대중"은 무관).
> 나란히 놓는 순간 독자는 **없는 대응을 읽는다.** 배치 실수가 아니라 **설계 실수**다.

### ② 그룹 간 관계 → 배치가 결정된다

| 관계 | 의미 | 배치 |
|---|---|---|
| **병렬** | 서로 대등하다 | 같은 형태로 나열 (3열 · 2×2) |
| **대비** | 서로 반대다 | **좌우 대칭** ← 좌우 분리가 **옳은** 경우 |
| **인과** | A가 B를 낳는다 | 좌(원인) → **화살표** → 우(결과) |
| **포함** | A가 B를 담는다 | 중첩 · 들여쓰기 |
| **순서** | A 다음 B | 플로우 도해 |

**"좌우로 나누는 것"은 대비·인과일 때만 옳다.**
대응 관계인데 좌우로 나누면 시선이 왕복해야 하고, 근접성 이득(d=0.79)이 사라진다.

### 관계 판정 체크리스트
- [ ] L5와 L3가 **1:1 대응**하는가? → 붙인다
- [ ] 대응이 **부분적**인가? → 억지로 개수를 맞추지 않는다
- [ ] 그룹끼리 **대비·인과**인가? → 좌우 분리 + 화살표
- [ ] 그룹끼리 **병렬**인가? → 같은 형태로 나열
- [ ] 나란히 놓은 것들이 **실제로 대응하는가?** (안 하면 오독을 만든다)

## 3. ★ 위계 분포 → 레이아웃 결정

**위계 태깅 + 관계 판정이 끝나면 레이아웃은 거의 자동으로 정해진다.**

| 위계 분포 | 레이아웃 | 근거 |
|---|---|---|
| **L1만** (L3·L4 없음) | **Statement** — 중앙 배치, 여백이 주인공 | 결론 하나를 각인 |
| L1 + L2 | Statement + Lead | 위와 같음 |
| **L5 1개** + L4 문단 | **좌 대형숫자 / 우 문단** (비대칭 4:8) | 숫자가 앵커 |
| **L5 2~4개** + L3·L4 | **좌 숫자열 / 우 설명열** (비대칭 5:7) | 숫자가 시선을 끌고 설명이 받는다 |
| **L3+L4 쌍 2개** | **2열 대비** (Highlight) | 대비·전후 |
| **L3+L4 쌍 3개** | **3열 카드** | 병렬 |
| **L3+L4 쌍 4개** | **2×2 그리드** | 병렬 |
| **L3+L4 쌍 5~6개** | **2단 세로 리스트** (한글 기본형) | 밀도 C3 |
| **L3+L4 쌍 7개+** | **표로 전환** 또는 **분할** | 밀도 C4 |
| L3가 **값 비교** (단위 섞임) | **Table** | table-layouts.md |
| L3가 **순서·위계·순환** | **Diagram** | diagram-layouts.md |
| L5가 **추이·순위·구성** | **Chart** | data-layouts.md |

### 판정 순서 (위에서부터)
```
1. L5(수치)가 있는가?        → 있으면 수치를 주인공으로 (좌 숫자 / 우 설명)
2. L3가 몇 개인가?           → 개수가 열 수를 정한다 (2→2열, 3→3열, 4→2×2)
3. L3가 값·순서·구조인가?    → 표 / 도해 / 차트로 전환
4. L3가 없는가?              → Statement (여백)
```

## 4. 층별 시각 사양 (D2 기준, 1280×720)

```css
/* 위계는 크기만이 아니라 4축으로 만든다: 크기 · 굵기 · 색 · 밀도 */
.L0-kicker  { font: 700 13px/1.4 var(--m-font); letter-spacing:.16em;
              text-transform:uppercase; color: var(--accent); }
.L1-assert  { font: 800 44px/1.22 var(--h-font); letter-spacing:-.02em;
              color: var(--text); }
.L2-lead    { font: 400 26px/1.5 var(--b-font); color: var(--muted); }
.L3-support { font: 700 24px/1.4 var(--h-font); color: var(--text); }
.L4-detail  { font: 400 19px/1.55 var(--b-font); color: var(--muted); }
.L5-figure  { font: 800 64px/1 var(--h-font); letter-spacing:-.03em;
              color: var(--accent); font-variant-numeric: tabular-nums; }
.L6-meta    { font: 700 12px/1.4 var(--m-font); letter-spacing:.12em;
              text-transform:uppercase; color: var(--muted); }
```

### 위계는 크기만으로 만들지 않는다

| 축 | 어떻게 쓰나 |
|---|---|
| **크기** | L5(64) > L1(44) > L2(26) ≈ L3(24) > L4(19) > L0·L6(12~13) |
| **굵기** | L1·L3·L5 = 700~800 / L2·L4 = 400 |
| **색** | L1·L3 = text / L2·L4 = muted / **L0·L5 = accent** |
| **밀도(자간·대문자)** | L0·L6만 tracking .12~.16em + 대문자 → **라벨로 읽힌다** |

**같은 24px여도 L2(400/muted)와 L3(700/text)는 완전히 다르게 읽힌다.**
크기가 부족할 때는 굵기·색·자간으로 층을 만든다.

## 5. 흔한 실패

| 실패 | 증상 | 처방 |
|---|---|---|
| **위계 2층** | 볼드 + muted 뿐. 슬라이드가 다 똑같이 생김 | **L5(수치)와 L0(kicker)를 찾아 넣는다** |
| **L1이 주제** | "매출 현황" | 주장으로: "매출은 3분기에 반등했다" |
| **L1이 둘** | "그리고"·"또한"으로 두 주장이 붙음 | 슬라이드 분할 |
| **L5 낭비** | 숫자를 본문에 묻어둠 | 승격해서 크게 |
| **L5 남발** | 모든 숫자를 크게 | 슬라이드당 **1~4개**. 나머지는 L4 |
| **위계 5층+** | 눈이 못 따라감 | L2나 L4를 지운다 |
| **accent 남발** | 강조가 3곳 이상 | **L0 + L5만** accent. L1·L3는 text |

## 6. 예시 — 이 문서를 슬라이드로

**인벤토리**
```
L0  Diagnosis
L1  카탈로그가 없는 템플릿을 있다고 등재하고 있었다
L2  취약한 게 아니라 잘못된 지도를 준 것이다
L5  0 (표)  ·  0 (도해)  ·  4 (죽은 링크)
L3  표 템플릿      L4  카테고리 자체가 없었다
L3  도해 템플릿    L4  Venn은 등재됐지만 실체 없음
L3  차트 눈대중    L4  값→픽셀 환산 규칙 부재
L6  claude-design v1.0 실측
```

**판정**
- L5가 3개 → **좌 숫자열 / 우 설명열 (비대칭 5:7)**
- L3+L4 쌍 3개 → 우측 리스트 3항목
- 위계 층수 = L0·L1·L2·L3·L4·L5·L6 → **L2를 뺀다** (L1이 이미 충분히 말함)

**결과**: 좌측에 `0` `0` `4` 대형 숫자, 우측에 3항목 설명. 상단에 kicker + assertion.
