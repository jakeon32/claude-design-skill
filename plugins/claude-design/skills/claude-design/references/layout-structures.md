# 레이아웃 구조 레퍼런스

> **레이아웃 = 어디에 무엇을 놓는가 (구조)**
> **스타일 = 어떻게 보이는가 (색·폰트·질감)**
> `레이아웃 × 스타일 = 결과물`
>
> [`style-reference-index.md`](style-reference-index.md)의 101종은 **스타일** 카탈로그다.
> 구조는 10~15개로 반복된다. **이 문서가 구조를 다룬다.**

**2026-07-14 신설.** 우리 스킬에 비어 있던 것:
**컨설팅 덱 구조 · 도해 중심 슬라이드 · 표 중심 슬라이드.**

## 0. 덱 전체를 관통하는 규칙 (BCG 112장 전수 관찰)

| 규칙 | 관찰 |
|---|---|
| **Action Title 100%** | **모든 슬라이드 제목이 문장이다.** "Context and objectives" 같은 명사구는 목차 슬라이드뿐. 본문은 전부 *"BCG was hired to help NYCHA do more with less"* 식 |
| **상단 라인 + 제목 밴드 고정** | 제목 아래 얇은 컬러 라인. 위치가 전 슬라이드 동일 |
| **섹션 TOC 반복** | 3 · 9 · 22 · 40쪽에 목차 재등장. **현재 섹션만 진하게, 나머지는 회색.** 독자가 위치를 잃지 않는다 |
| **하단 좌: 출처 / 우: 페이지** | 예외 없음 |
| **색은 단색 + 회색** | 녹색 하나. 강조는 **면적이 아니라 위치**로 |
| **밀도가 매우 높다** | 우리 D3(배포용)보다 조밀. **읽는 문서**이지 발표용이 아니다 |
| **도해가 텍스트를 대체** | 설명을 문장으로 늘어놓지 않고 박스+화살표로 구조화 |

> ⚠️ **이 덱을 그대로 베끼면 안 된다.** 이건 **읽는 문서(D3)** 이고 영문이다.
> 한글은 자폭이 2배라 같은 자리에 절반밖에 못 들어간다.
> **구조를 가져오되 밀도는 우리 규범(density-rules.md)으로 재계산할 것.**

## 1. 프로세스 플로우 (5단계 가로) — `bcg_005`

**언제**: 프로젝트 단계·업무 흐름을 한 장에.

```
┌─ Action Title ────────────────────────────────┐
│ [Phase 1] → [Phase 2] → [Phase 3] → [Phase 4] │  ← 상단: 단계 박스 (색 채움)
│                                               │
│  ┌──────┬──────┬──────┬──────┐                │  ← 하단: 각 단계의 산출물
│  │ 활동 │ 활동 │ 활동 │ 활동 │                │     (열 = 단계와 정렬)
│  │ 활동 │ 활동 │ 활동 │ 활동 │                │
│  └──────┴──────┴──────┴──────┘                │
└───────────────────────────────────────────────┘
```
**핵심**: 상단 단계 박스와 하단 산출물 열이 **세로로 정렬**된다.
독자가 "이 단계에서 무엇이 나오나"를 눈으로 따라간다.

## 2. 벤치마킹 매트릭스 (표 × 히트맵) — `bcg_015` · `bcg_028`

**언제**: 여러 대상 × 여러 지표 비교. **표가 주인공.**

```
┌─ Action Title ─────────────────────────────────┐
│         │ 대상A │ 대상B │ 대상C │ 대상D │      │
│ 지표 1  │  ■■   │  ■    │  ■■■  │  ■    │      │  ← 셀에 막대/색으로 값
│ 지표 2  │  ■    │  ■■■  │  ■■   │  ■■   │      │
│ 지표 3  │  ■■■  │  ■■   │  ■    │  ■■■  │      │
│                                                │
│ [범례]                          [출처]         │
└────────────────────────────────────────────────┘
```
**핵심**:
- 셀에 **숫자만 넣지 않는다.** 막대·색으로 **크기를 보이게** 한다 (인라인 바 / 히트맵)
- 행 = 지표, 열 = 대상. **비교 방향이 가로**
- **우리 규범 연결**: `table-layouts.md` §7 (히트맵은 동일 단위 격자에서만)

---

## 3. 스윔레인 프로세스 (역할별 흐름) — `bcg_017`

**언제**: 여러 주체가 관여하는 절차. "누가 무엇을 하는가".

```
┌─ Action Title ─────────────────────────────────┐
│ 역할A │ ○──→○                                  │
│ ─────────┼──────────────────────────           │
│ 역할B │      └→○──→○                           │
│ ─────────────────┼──────────────────           │
│ 역할C │              └→○──→○ (완료)            │
│                                                │
│ 소요기간: ├── 1~6개월 ──┤── 60일 ──┤           │  ← 하단 타임 축
└────────────────────────────────────────────────┘
```
**핵심**: 가로 = 시간, 세로 = 역할. **넘겨받는 지점이 눈에 보인다.**
하단에 **소요 기간 축**을 깔면 병목이 드러난다.

## 4. 조직도 (Before → After) — `bcg_019`

**언제**: 구조 재설계 제안.

```
┌─ Action Title ─────────────────────────────────┐
│  현재 구조          │  제안 구조 (2안)         │
│  ┌───┐              │  ┌───┐      ┌───┐        │
│  │   │              │  │   │      │   │        │
│  ├─┬─┤              │  ├─┴─┤      ├─┬─┤        │
│  │ │ │              │  │   │      │ │ │        │
│                     │                          │
│  ─────────────────────────────────────────     │
│  핵심 변화: 계층 제거 · 통합 · 관리폭 확대      │  ← 하단 요약 바
└────────────────────────────────────────────────┘
```
**핵심**:
- **좌우 대비**가 구조를 말한다 (관계 = 대비 → 좌우 분리가 **옳음**)
- **하단에 "핵심 변화" 요약 바**를 깔아 So-What을 못 박는다

---

## 5. 고밀도 텍스트 2단 (Executive Summary) — `bcg_023`

**언제**: 요약. 텍스트가 많을 수밖에 없을 때.

```
┌─ Action Title ─────────────────────────────────┐
│ ● 굵은 리드 문장 (결론)                        │
│   – 하위 근거 1                                │
│   – 하위 근거 2                                │
│                                                │
│ ● 굵은 리드 문장 (결론)                        │
│   – 하위 근거 1                                │
│   – 하위 근거 2                                │
└────────────────────────────────────────────────┘
```
**핵심**:
- **2층 불릿만.** 3층 이상 금지
- **1층 = 볼드(결론) / 2층 = 일반(근거)** — 위계가 굵기로만 갈린다
- 이건 **읽는 문서(D3)** 전용. 발표용(D1/D2)에 쓰면 못 읽는다

## 6. 개념 도해 (박스 + 화살표) — `bcg_032`

**언제**: "무엇이 무엇으로 바뀌는가"를 그림으로.

```
┌─ Action Title ─────────────────────────────────┐
│  ┌────┐  ┌────┐          ┌──────────┐          │
│  │    │  │    │  ══════▶ │  통합된  │          │
│  │    │  │    │          │  운영모델 │          │
│  └────┘  └────┘          └──────────┘          │
│  분산된 현재              목표 상태             │
│                                                │
│  [하단 강조 바] 핵심 메시지 한 줄               │
└────────────────────────────────────────────────┘
```
**핵심**: 텍스트로 "통합하면 좋다"고 쓰지 않는다. **분산 → 통합을 그림으로 보인다.**
하단 **색 채움 바**에 결론 한 줄.

## 7. 섹션 TOC 반복 — `bcg_003 · 009 · 022 · 040`

**언제**: 섹션이 바뀔 때마다.

```
┌────────────────────────────────────────────────┐
│  Table of Contents                             │
│                                                │
│  ① 프로젝트 배경         ← 회색 (지나감)        │
│  ② 기회 식별 접근법      ← 회색                 │
│  ③ 핵심 발견과 제안      ← 진하게 (현재)        │
│  ④ 비용 절감            ← 회색                  │
└────────────────────────────────────────────────┘
```
**핵심**: **현재 섹션만 진하게.** 독자가 112장짜리 덱에서 길을 잃지 않는다.
> 우리 덱이 10장을 넘어가면 이걸 넣는다.

## 9. 수집 계속하기

**비어 있는 것만 채운다.** 이미 있는 스타일을 또 긁으면 중복만 쌓인다.

```bash
# 공개 컨설팅 덱 PDF → 콘택트시트 → 구조 태깅
curl -sL -o deck.pdf "<PDF URL>"
python -c "
import fitz
doc = fitz.open('deck.pdf')
for i, p in enumerate(doc): p.get_pixmap(dpi=60).save(f'p{i+1:02d}.png')
"
# 콘택트시트로 한눈에 보고, 새로운 구조만 layout_refs/ 에 고해상도 저장
```
