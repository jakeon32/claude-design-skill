# 스타일 레퍼런스 인덱스

> ## ⚠️ 이름 정정 (2026-07-14)
> 처음 이 문서를 "레이아웃 레퍼런스"라고 불렀는데 **틀렸다.**
> **101종은 스타일(색·폰트·분위기) 카탈로그다. 레이아웃(구조) 카탈로그가 아니다.**
>
> 스타일은 101가지지만 **구조는 10~15개로 반복된다**:
> 표지(좌 텍스트 / 우 이미지) · 3열 카드 · 좌우 2단 · 풀블리드 이미지 · 대시보드 그리드 …
>
> **레이아웃 = 어디에 무엇을 놓는가 (구조)**
> **스타일 = 어떻게 보이는가 (색·폰트·질감)**
> `레이아웃 × 스타일 = 결과물`
>
> **→ 레이아웃 구조 레퍼런스는 따로 수집해야 한다** (§확장 계획).

**2026-07-14 신설.** 그 전까지 이 스킬에는 "이렇게 생긴 덱"을 가리킬 **실물 레퍼런스가 없었다.**
스타일 문서(`styles/`)는 색·폰트·분위기를 *글로* 서술할 뿐 **실물이 없었고**,
레이아웃 문서는 개별 템플릿만 있었다.

## 자산 위치

```
site/assets/thumbs/{1..101}.jpg          — 스타일별 대표 시트 (한 장에 4~9슬라이드 미리보기)
site/assets/slides/{NNN}_{Name}/         — 일부 스타일의 상세 슬라이드 PNG
site/decks/020/                          — 실제 제작 덱 (GroundK×보람그룹 제안서 20장)
```

> ⚠️ 원본은 `Downloads/site.zip`. 레퍼런스로 쓰려면 압축을 풀어 참조한다.
> 콘택트시트를 다시 만들려면 PIL로 6×9 그리드(300×200 셀) 2장이면 101종이 한눈에 들어온다.

## 이 라이브러리를 쓰는 법

### 1) 덱을 만들기 전 — 레퍼런스부터 고른다
```
"제안서인데 데이터가 많다"        → A 그룹 (35 · 94 · 93)
"브랜드 소개, 사진이 좋다"        → B 그룹 (25 · 22 · 31)
"한 문장으로 밀어붙인다"          → C 그룹 (8 · 21 · 19)
"서비스 구조를 설명한다"          → D 그룹 (46 · 47)
"내부 교육, 딱딱하지 않게"        → E 그룹 (57 · 59)
```

### 2) 정보밀도로도 고른다 (density-rules.md와 연결)
| 밀도 | 적합 그룹 | 예 |
|---|---|---|
| **C1 희소** (항목 1~2) | B, C | 25 · 8 · 22 |
| **C2 보통** (3~4) | C, D, G | 19 · 46 · 020 |
| **C3 조밀** (5~6) | A, D | 35 · 47 |
| **C4 과밀** (7+) | **A만** — 그 외는 분할 | 94 · 93 |

### 3) 흡수할 디자인 요소 (→ `design-elements.md`)
레퍼런스에서 반복적으로 관찰되는 요소:
- **eyebrow + 틱** — 섹션 라벨 위 짧은 컬러 바 (19 · 020)
- **대형 흐린 번호** — 빈 공간을 채우는 배경 숫자 (24 · 020의 `.vnum`)
- **카드 상단 컬러 보더** — 4px 액센트 (020)
- **색면 분할** — 좌 색면 / 우 사진 (8 · 21 · 020 표지)
- **헤더 밴드** — 섹션명 좌 / 페이지 우 + 얇은 라인 (35 · 020)
- **흑백 사진 통일** — `grayscale(1) contrast(1.06)` (020 · 22 · 92)

## ⚠️ 레퍼런스를 볼 때 함정

1. **템플릿의 텍스트 양을 믿지 마라.** 대부분 영문 기준이고, **한글은 자폭이 2배**라
   같은 자리에 절반밖에 못 넣는다 (→ `density-rules.md` §2).
2. **폰트 크기를 그대로 베끼지 마라.** 캔버스 크기가 다르면 환산해야 한다.
   1527px 캔버스의 14.5px = 1280px 기준 **12.2px** — 배포용 하한(16px)에도 미달이다.
3. **"예뻐 보이는 것"과 "읽히는 것"은 다르다.** 레퍼런스는 대개 **더미 텍스트**라
   실제 내용을 넣으면 넘친다. 반드시 줄 예산을 먼저 계산할 것.

## 확장 계획

- **② 레이아웃 구조 수집** — **비어 있는 것만.** 이미 있는 스타일을 또 긁으면 중복만 쌓인다.
  - McKinsey / BCG / Bain 공개 덱 (고밀도 컨설팅 구조)
  - 도해·다이어그램 슬라이드
  - 표 중심 슬라이드
  - (기존 `x-scraping` puppeteer 인프라 재사용 — 새 도구 불필요)
- **③ 자가 축적**: 우리가 만든 덱 중 **승인된 것만** 등재. 실패작은 넣지 않는다.
  쌓이면 "우리 스타일"이 된다.
